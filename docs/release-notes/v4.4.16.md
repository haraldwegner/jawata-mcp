# jawata-mcp v4.4.16

**`run_tests` starts in the module's own folder and keeps a library's DEBUG output out of its tail, a boot no longer leaves its folders in `/tmp`, and the engine now separates from the headless host that runs it.**

## What went wrong

- **`run_tests` started the test JVM in the JDT project's folder.** For a project managed by jawata-studio that folder is a link folder in studio's cache, so a test that reads a path relative to its module could not find it. In java-design-patterns, `page-object` ran 4 of 4 red with a 404 for `../sample-application/...`, while `singleton` ran 19 of 19 green. Maven and Gradle start a module's tests in the module's own folder.
- **The `run_tests` output tail could be a library's DEBUG log.** A library whose logging nobody configured filled all 100 lines of `stdoutTail` and hid the one INFO line that gave the cause.
- **Every boot left two folders in `/tmp`.** The test workspace and the OSGi configuration folder were removed only by a run through `build/run-suite.sh`. By 2026-10-24 one machine held 1,321 workspace and 1,782 configuration folders, 41.6 GB. A boot that failed before the framework started left its folders too.
- **The workspace watcher did not start when the OS refused it a watch service**, which is what happens when the user's inotify instances are used up. This was the second known limit of 4.4.15.
- **`tools/list` did not come in the same order on every start.** Two tools held their kinds in a `Set.of`, whose order changes per process.
- **A plan step was built over every loaded project in full**, and a build that threw an unchecked exception escaped the plan loop with earlier steps applied and not undone. A change that was applied was not undone when something threw before the answer.

## What changes

- **`run_tests` starts the test JVM in the folder of the module that owns the tests.** The test source roots come from the model, and the module is the one the importer's own walk names. The mutation runner starts there too.
- **The `run_tests` output tail drops DEBUG and TRACE lines and ends with a line saying how many it left out.**
- **A boot removes the two folders it creates**, on a normal close, on a refused boot and from a shutdown hook. A deletion that fails is counted and named on stderr. A halt by the boot watchdog still skips them.
- **When the OS refuses the watcher a watch service, it follows `workspace.json` by polling.**
- **`tools/list` is published in one order on every start**, and the end-to-end gate compares it with its golden byte for byte.
- **A plan step is built over the projects it touches and the projects that require them, incrementally**, required projects first. A build that fails for any reason fails the step, and a change that was applied is undone when anything throws before the answer.
- **The engine no longer assumes the headless host.** Two new bundles carry the split: `org.jawata.spi` holds the contracts between the engine, a host and a language, and `org.jawata.resident` holds the headless host. The engine names no Java type and no language; each bound language checks its own declarations against the published tools and supplies its own tools. An engine with no language bound reports that it is loading through `health_check`. The dist publishes the same 44 tools.

Each change has a test that fails without it.

## Behaviour changes

- **A project a plan step did not touch no longer fails an `apply_plan` step for errors it already had.**
- **`get_diagnostics` caps its answer at `maxResults` on the AST path as well.**
- **A source root that does not exist as a folder is left out of a project's roots.**
- **Plan actions called with a `projectKey` may run over the unscoped Java service.** This has not been measured.

## Known limits

- **On Windows, a path given in short-name form (for example `C:\Users\RUNNER~1\...`) is not matched to the project loaded under its long name.** The fix is planned for the OS-coverage sprint.
- **`CoverageService` and `MutationService` still import the Java provider's jar locator**, so the coverage and mutation tools are not yet independent of the Java provider's package.

Works with jawata-studio 4.4.9.
