# jawata-mcp v4.4.1

**A hired seat now receives its own rules, a hired Claude talks only to the jawata that hired it, and macOS and Windows build green again.**

## What went wrong

- **A hired seat never received its own rules.** The `hire` tool read a seat file's settings (which agent program, which model, which tools, which limits) and dropped the text below them: what the seat is, and what it must refuse. A hired cataloguer ran as a general-purpose agent holding someone else's request.
- **A hired Claude started with the user's whole setup.** It loaded every MCP server, setting and hook the user has configured. In Sprint 28g a one-word answer cost $2.26 that way. The seat's tool limit named jawata's tools by their short names (`inspect`), which Claude does not recognise, so the limit applied to nothing.
- **The bug check reported a file it could not read as clean.** When `find_quality_issue` with `kind=bugs` could not read a file, it answered success with zero issues, so the automatic architect watch stayed silent about an edit it never inspected.
- **The 4.4.0 macOS and Windows builds failed.** A hired run's journal row was lost when a path was longer than its column, and four tests failed on those two systems because of how the tests were written.

## What changes

- **The seat's rules go to the agent first, then the request.** The written record of the run shows that combined text, so a reader sees everything the agent was given.
- **A hired Claude gets one MCP server: the jawata that hired it.** It skips the user's settings and hooks, and its tool limit uses the names it actually sees (`mcp__jawata__inspect`). Measured on a real hire: the seat's rule was followed, the agent used the resident's own `health_check`, and the run cost $0.10.
- **A file the bug check could not read is now a refusal that says why**, and a whole-project scan lists every file its count does not cover. The watch logs such a refusal instead of staying silent.
- **macOS and Windows build green.** A journal row now fits its columns, and the four tests are fixed. On Windows the hire tests are skipped and declared in the Windows skip list, which now names Sprint 28h as the place that owns the Windows hire.

## Known limits

- **Only an HTTP resident gives a Claude hire its own endpoint.** A stdio resident cannot be reached by a second process, so a Claude hire from it keeps the user's own setup.
- **The one-server start covers Claude only.** Cursor, Copilot and Codex are started exactly as in 4.4.0.
- **No hire has run on Windows.** Sprint 28h owns that.

Works with jawata-studio 4.4.1.
