# v3.15.1 — the as-built pass removes a dead API

A patch on v3.15.0, from the sprint's own close-out audit.

## `clearTombstone` is gone

v3.15.0 shipped `ExperienceStore.clearTombstone` with **zero production callers**. The
as-built wiring pass — which resolves every delivered capability to a symbol and runs
its incoming call hierarchy — found its only reference in the whole workspace was the
recovering-store decorator forwarding to its own delegate.

Reviving a tombstoned source never needed the method: a reseed wipes the tombstone
table and then re-writes only the refs it did **not** load, so a source the reseed
brings back is revived by not being re-tombstoned. That is what its test had been
proving all along.

Deleted rather than baselined, which is this codebase's standing treatment of
unreachable API. If a later sprint wants an explicit revive verb, it arrives together
with its caller.

No behaviour changes. Stores at schema v14/v15 are unaffected; the tombstone write,
the crawl-side skip, the stats count and the reseed's own revival all work exactly as
they did in v3.15.0.
