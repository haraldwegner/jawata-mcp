# jawata v3.7.0 — Prove the engine

Sprint 28's engine half: not new capabilities — proof that the claimed ones
actually operate, each behind a check that fails when they stop.

- **Every declared build system now actually loads.** Maven, Gradle, Bazel,
  Eclipse PDE and plain Eclipse each have a committed sample project the
  importer really opens, with a test per property: source folders found,
  dependency jars resolved, build output excluded, the right Java language
  level, and one real question answered about the code. Bazel — previously
  "detected" and never once loaded — now derives its language level from the
  `javacopts` its projects declare.

- **Main and test code are told apart by the project model, not by a path
  guess.** The classifier reads each source root's test attribute; on jawata's
  own repository `scope=main` and `scope=test` now return different and
  correct sets (72 vs 61 warnings, no test-bundle file in main — the live
  numbers that re-closed issue #9).

- **"Called only by tests" is now a detector.** A public member whose every
  caller lives in test code is the signature of built-but-never-connected —
  the defect class that shipped an inert release in v3.4.0. It runs in the
  standard quality sweep unprompted, and a release gate runs it against this
  repository with a committed baseline.

- **The end-to-end test is a release gate, not a habit.** It runs in the
  release workflow against the built jar over the real endpoint, from a
  committed 48-entry fixture with rejected, superseded and near-duplicate
  entries — and the release fails if any promise it protects goes red:
  recall by meaning, a rejected note never returning, nonsense never vouched,
  keyword-only degrade, no similarity numbers in answers.

Client-side halves of the same sprint (the hook binary, its deploy, the
silence log) ship in jawata-studio v3.7.x.
