# jawata-mcp v4.4.13

**Lombok projects are understood again, and `run_tests` says when a project does not compile instead of blaming its input.**

## What went wrong

- **Lombok support was silently off in every 4.4.x engine.** The distribution stopped shipping `lombok.jar` when the build moved to Maven, and jawata-studio starts a Lombok workspace's engine with that jar as an agent only when it finds it beside `jawata.jar`. Without it, every member Lombok generates (getters, `LOGGER`, constructors) read as a compile error: the java-design-patterns workspace reported 3,445 errors, every one sampled a Lombok member, while `health_check` called all 194 projects healthy. On one of its projects: 12 errors without the agent, 0 with it.
- **`run_tests` refused a project that does not compile as `INVALID_PARAMETER`**, with the hint to check the tool's input schema, although every argument was valid.

## What changes

- **The distribution ships `lombok.jar` (1.18.36) beside `jawata.jar` again.** A new release gate, `build/lombok-agent-probe.sh`, starts two engines on a small Lombok fixture: without the agent it must report the missing generated getter, with the agent zero errors. It failed on the 4.4.12 distribution and passes on this one; the release job also refuses a distribution without the jar.
- **`run_tests` and `run_tests(action=coverage_mutation)` refuse a project that does not compile as `PRECONDITION_NOT_MET` with the reason `PROJECT_DOES_NOT_COMPILE`.** The message still names the first compile error. Both refusals are covered by a test that fails with the old answer.

## Known limits

- **`health_check` still calls a project healthy while Lombok comprehension is off,** for example when an older studio starts this engine without the agent. Reporting it as its own field is filed for Sprint 28h.
- **A field recording taken before this release counts the old refusal as `run_tests/…/INVALID_PARAMETER`;** from this release it is `PRECONDITION_NOT_MET`.

Works with jawata-studio 4.4.8, which also finds Lombok when it is declared in a parent build file or a `lombok.config` above a project, and asks every project of the workspace.
