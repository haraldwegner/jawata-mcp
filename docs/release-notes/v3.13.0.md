# jawata-mcp v3.13.0

The knowledge store is rebuilt from files, and the engine learns to consult
every cue.

## The store is derived, and that changes what "saving" means

The store is now refilled from a reviewed file substrate. Any quality doubt is
answered the same way every time: **fix the files, wipe, reseed.** A store you
can only correct by editing rows is a store whose quality you can never
re-establish.

That has a sharp edge which the product now states rather than leaving to be
discovered: **a direct `record` writes a row with no file behind it, and the next
reseed removes it** — silently, because the count check afterwards asserts the
file count and still passes.

- `experience(kind=stats)` gains a `substrate` block naming where story files
  belong, derived from the entries' own source paths. A store with no ingested
  entries returns `root: null` **with an instruction not to choose a directory**:
  a plausible path there is indistinguishable from a correct one at the call site.
- A **reseed admits stamped stories only** (`reviewed:` in the frontmatter). The
  check is deterministic on purpose — it asks whether a review HAPPENED, never
  whether the story is good. Judgement lives in the cold reader in front of
  ingest, because an ingest that judged content would be an unreviewable
  intelligence in the one place nobody watches. An ordinary `load` does not
  require the stamp: loading is how notes reach the store, reseeding is how the
  store is rebuilt, and only the second is a claim that anything was checked.

## Every cue in a prompt reaches the store

The recall hook derived up to five cues from a prompt and asked about them one at
a time, **exiting on the first that answered**. Four cues' knowledge was never
fetched — and from the reading agent's side, a cue that was never asked is
indistinguishable from a store that has nothing for it.

`recall` now accepts `symbols` and `symptoms` arrays and unions the answers in
one call, honouring the caller's own precedence order. It composes rather than
re-ranks: merging the score spaces of five separate queries would invent a
comparison nothing computed. An UNAVAILABLE answer returns immediately and is
never averaged away by a later cue that happened to work.

`recall` also accepts a `session`, and an entry already shown in that session is
withheld — **and the withholding is reported**, because an entry held back because
the reader already has it and an entry the store does not have are opposite facts.

## The pattern catalogue answers design questions

All five frozen design questions — written before the extractor existed, none
naming its own pattern — return their pattern through the front door:
`circuit-breaker@1 strategy@3 saga@1 observer@1 builder@1`.

A nominated **reference** now carries the address it can be opened at; an
**experience** deliberately does not, because an experience's `source_ref` is the
file path of whoever recorded it.

The catalogue is typed `reference`, not `lesson`. A published pattern was not
lived by anyone here, so it has no outcome — and the value invented so 187 library
descriptions could satisfy a rule written for experiences was that rule announcing
it was wrong about them.

## What was shown, what was chosen, and what nobody could answer

- `experience(kind=review_sweep)` returns two lists that are never merged: entries
  shown often and chosen never (consider removing), and questions asked repeatedly
  that nothing answered (consider writing). It reports its own dropped-write count,
  because a low engagement rate computed over lost rows means "we failed to record
  it", not "nobody engaged".
- `experience(kind=delete, ids=[…])` removes exactly what you name, and writes an
  archive of those entries **first**. A failure to write the archive cancels the
  delete. `prune` is untouched and remains the blunt instrument.

## Fixes

- **`decide` recorded "the caller chose nothing" for a malformed selection.** A
  single id sent as a bare string was read as an empty selection — and that verb's
  whole contract is that choosing none is a real answer, so the store ended up
  holding "nothing applied" about a question somebody had answered,
  indistinguishable afterwards from an honest absence. Present-and-unreadable is
  now refused by name; absent still means chose-none.
- Numeric arguments that are present but unparseable are refused rather than
  silently defaulted — a default there returns lists computed at thresholds nobody
  chose, and they read as facts about the store.
