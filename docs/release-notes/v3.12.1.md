# jawata-mcp v3.12.1 — the store stops wedging

## The experience store is no longer a global chokepoint

A single slow read used to stop the whole server. Every read method held the
store's instance lock across its database I/O, so one read parked in a socket
that never answered took everything with it — the original incident had 66
threads queued behind one of them, and the same shape was caught live on a
3.11.1 resident this week: `health_check` replying instantly while every real
tool call timed out, because recording a tool's usage row needs that same lock.

Reads now run on their own pooled connections and take no lock at all. A read
that hangs costs one of four pool slots instead of the server; when all slots
are busy the store says so, and says **busy** rather than "wedged", because
four healthy concurrent reads look identical from the inside.

Writers are deliberately untouched — they still serialise on the one shared
connection, so the guarantee that the learner's writes and the store's own
never interleave holds exactly as before, pinned by a test.

Verified rather than argued: under six concurrent threads hammering recall,
stats and list, a thread dump shows **no thread holding the store lock across a
socket read, and none waiting on it**. Closes **#37**.

## Impacted-test selection is reachable, and fenced

`build/impacted-tests.sh` asks a running resident which test classes a change
impacts, and `build/run-suite.sh` gains an opt-in `--impacted` flag that
consumes it. Selection narrows the inner development loop only — every gate run
calls the script without the flag and runs the whole suite.

It narrows only when the evidence can carry the claim, and says why when it
cannot: attribution must exist, must not declare itself partial, must have been
recorded at a revision that is an ancestor of HEAD, and must account for every
source file changed since. Any failure prints its reason and runs everything.

That last rule is load-bearing today, because the selection tool derives
symbols from added files and none from modified ones (**#40**), which makes a
mixed change come back with a plausible, wrong, narrow answer.
