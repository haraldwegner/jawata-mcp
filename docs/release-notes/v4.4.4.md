
# jawata-mcp v4.4.4

**The experience store no longer shuts itself down when a recall times out.**

## What went wrong

- **A recall that ran past its deadline interrupted the thread that was reading the database file.** `ExperienceRetrieval.within` released the caller on the deadline and then called `task.cancel(true)`, which interrupts the reader. A Java file channel closes for good when its thread is interrupted, so H2 panicked, closed the database for every engine sharing the file and failed the page it was writing. The store's own error trace shows it in order: `ClosedByInterruptException` in a retrieval worker's read, a failed write, then "The database has been closed" (90098) from Oct 12 for three days, and a "file corrupted" (90030) error a day after the first closure.
- **A second path did the same.** A thread interrupted while it waited for a free read slot was answered `null`, which sent it on to read through the shared connection with its interrupt flag still set.

## What changes

- **The recall deadline releases the caller and leaves the reader alone.** `cancel(false)`: the abandoned read finishes on its own and its answer is discarded.
- **A thread interrupted while waiting for a read slot is refused** with a named error instead of being sent on to read.
- **Two new tests**, each red with its fix put back and green with it in place: `an_expired_budget_never_interrupts_the_read_in_progress` and `anInterruptedWaiterDoesNotReadThroughTheSharedConnection`.

## Also in this release

- **The hire answer says why a run did not exit cleanly:** `exitCode` and `stderrTail`.
- **`inspect(kind=suite_policy)`** answers the suite's accepted aborts as data, and `run_tests` `coverage_mutation` publishes `errorCount`, so a mutation run can be a hire gate and a surviving mutation fails it.
- **A seat can declare `answer_gates`** in its frontmatter; the hire path runs them as plan steps. The PM seat declares `upward_message`: an upward message that states no fact, cause and cost is refused in the hire's record.

## Known limits

- **The interrupt is proven on a stalled-read fixture, not on a real file channel.** The two tests show the reader is no longer interrupted; none of them reproduces H2's file-channel closure itself. The cause is read from the store's error trace.
- **An abandoned read keeps its H2 session until its read returns.** The retrieval pool is bounded at eight workers, so a store that stops answering still fills the pool and callers are told it is saturated.
- **This does not repair a store that is already corrupt** and does not add backups. A daily and before-first-write backup is not in this release.

Works with jawata-studio 4.4.1. No studio release is needed.
