# jawata-mcp v4.1.0

## Fowler's catalogue, and every fix reachable from the finding that names it

jawata performed **17** of Martin Fowler's 66 refactorings completely, and 6 more in
part. It now performs **62 of the 66**. It detected 17 of his 24 code smells; it now
detects **22 of the 24**. The remaining four refactorings and two smells are declined
in writing, each with its reason, and none of the six is silently absent.

Both figures are computed rather than claimed. The catalogue is the published one —
66 refactorings, 24 smells — and each row is joined against the operations the product
actually publishes at start-up, so a renamed or dropped operation lowers the count and
names the refactoring that stopped being performed.

## The half that matters more than the count

A tool that performs a refactoring is not much use if the report that found the problem
cannot tell you how to run it. Before this release, **18 of 78 shipped operations were
named by any cure**, and a finding that did name one often handed over an address the
door would then refuse.

Three things changed.

**A finding carries where its fix would run.** Every routed detector now emits a fully
qualified address, not a bare identifier. Thirteen detectors were emitting something no
door could accept; they were found by driving each cure's own door with each finding's
own address, which is now a permanent check rather than a one-off audit.

**The instruction is spelled the way the door accepts it.** One door selects on
`direction` rather than `kind`; every address rendered for it named the wrong parameter,
so seven published instructions could not be followed. The renderer now asks each door
for its own selector.

**A refusal names the smaller step it leaves.** Where an operation declines because
something must happen first, it hands back that step as an operation with an address —
not as a refactoring name in a sentence. Where no smaller step applies, it says so, and
that absence is asserted rather than assumed.

The result: **30 of the 30** refactorings that have a detector are now offered by it.

## A verdict that stopped punishing choice

The rule deciding whether to instruct or advise counted the routes a smell had. One
runnable fix meant "run this"; two meant "consider these" — so teaching the product a
second, better cure made its advice *less* useful, and four smells were being demoted
for having more than one answer. The rule now turns on whether any fix is runnable at
all, and where a smell has several, each carries the sentence that tells it from its
neighbours. `lazy_class` offers both of its shipped fixes, each saying which case it is
for.

## Smaller and more honest at the front

The published tool count falls **46 → 42**. Six overlapping tools were folded into the
front doors that already covered them; every retired name still answers, with a pointer
to its replacement. The nine refactoring doors, their descriptions and the lists that
check them are now produced from one source rather than four hand-written copies that
had drifted apart — a gap in one of those copies had left eleven shipped operations
publishable by nobody.

## Two defects found by using the product on itself

- The change reviewer stored its baseline under a key longer than the column holding
  it, so the write always failed and every pre-existing finding in a file was reported
  as newly introduced on every edit.
- The naming check could not skip test sources — 1,533 findings on this repository,
  almost all deliberate test method names. It now takes the same switch every other
  check takes.

## Declined, with reasons

Four refactorings are not operations here: Change Value to Reference, Combine Functions
into Transform, Introduce Assertion and Substitute Algorithm. Two smells are not
detected: Mysterious Name (whether a name is mysterious is meaning, not shape — the
mechanical part ships as the naming check) and Comments. Each declination is recorded
where a reader meets it, and a check refuses the state of being neither detected nor
declined.

### Gates

Suite **2836 total / 2834 succeeded / 0 failed / 2 aborted** (the standing corpus pair,
which needs a corpus this machine does not carry) · compile 0 errors, 0 warnings ·
every deliverable exercised through the product's own front door against the built
artifact, with no result reported unproven.
