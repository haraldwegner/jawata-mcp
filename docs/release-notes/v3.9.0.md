## jawata-mcp v3.9.0

**A wrong-workspace question answers itself.** A machine running several jawata
servers (one per workspace) previously gave the agent no way to tell which
serves what. Now every server introduces itself: the connection instructions
carry the workspace name and its project roster, a symbol that is not found
says *where* it looked and redirects to the right server, and an empty search
steers instead of reading as "does not exist".

**The engine's Windows behaviour is an assertion, not a hope.** The TestHost
kit's fake executables are Java-launcher based because a Windows `.cmd`
shreds program arguments — the argv question that gated Windows coverage is
now answered by a test that runs on the three-OS CI matrix.

**Three long-standing defects got their verdicts** (Sprint 28a Stage 5):
the wrong-Java-level defect is confirmed fixed since v3.7.0; the
1139-errors-across-20-projects mass is fully diagnosed into #3 + #11
(dependency resolution, not code) and reproduces identically across OSes;
the oversized source-lookup reply is still broken and filed as #23.

**The release gate earned its keep**: the first v3.9.0 run was refused by the
hollow-wiring gate for two test-only public members — both fixed, baseline
tightened by two newly-wired members.

Full serial suite: 1819/1821, 0 failed, 2 corpus-gated skips.
