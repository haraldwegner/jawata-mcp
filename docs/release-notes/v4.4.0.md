# jawata-mcp v4.4.0

**The refactoring tools stop failing on real code, the engine can hire a coding agent to do a seat's work and say what that agent changed, and the Fowler catalogue becomes data.**

This is the last 4.x release. It follows a measured refactoring sprint on a real trading codebase: the analysis half of jawata held completely, the change tools were used twelve times, four of those changes were kept, and 47 of the 298 hand edits that followed had a working tool sitting unused. This release repairs the tools that failed and gives the studio what it needs to stop the hand edits.

## What went wrong

- **Eight engine defects found by that sprint.** `extract kind=method` answered `INTERNAL_ERROR` on one file with no phase named; `change_method_signature` rewrote the enclosing call instead of the target; it pasted a default where the variable did not exist; the forked test runner killed every Mockito test; nothing promoted a nested type to its own file; one rename answered with 167,785 characters; adding a record component rewrote all 78 sites with no overload mode; and a lane filter silently dropped the whole pattern catalogue from a design question.
- **A tool's own answer could say "no code changed" over a run it could not see.** A hired run that only used writers with no undo (format, quick fix, dependency edits) read as harmless.
- **Test selection ran the whole suite.** The product's own change-reachable selection was used by nothing.
- **The refactoring catalogue lived in the test tree.** Nothing in the product could say which of Fowler's refactorings it performs.

## What changes

- **Seven of the eight defects are fixed**, each with a recipe that fails before and passes after. The eighth, the extract-method internal error, now answers with the phase that threw, the exception and its top four frames, so its root cause is read from the engine's own answer.
- **Five smaller defects and four tool changes.** Retargeting a call onto an argument, move-method asking about the old owner, deleting a public member nothing references, and state from nullable fields. One new tool: delete an anonymous implementation and make its target implement the interface.
- **`org.jawata.catalogue` is a module of its own.** 66 refactorings and 24 smells as data, keyed by origin. The Java engine declares which it performs — 62 of 66, recomputed at boot from what its doors publish — and refuses to start if its claim and its doors disagree.
- **Tests are selected by compiler reach.** `run_tests` runs only the tests the coverage evidence says a change reaches and widens itself, with a printed reason, where that evidence cannot carry the claim.
- **A hire path.** `hire` runs a seat on Claude, Cursor, Copilot or Codex with a brief, ceilings on wall clock, iterations, cost and tool steps, and a written record. The record states how many of the run's calls changed code and names every blind spot behind a "no": a shell, an unclassifiable call, a stream the brain only partly shows, an unreadable line, a run cut short. Containment is reported per brain: on two of the four, a seat told only to read can still write, and the record says so rather than claiming a bound.
- **The store and the cataloguer.** Applied samples are counted, duplicates and anchors are checked before a job is written, coverage follows use, and the profiler tells waiting from working.
- **Front doors dispatch through the delegate they look up.** `data` and `change_method_signature` kept a second eleven-arm switch beside the routing table they publish; they now have one table.

## Known limits

- The hire path's containment claim is unmet on two of the four brains.
- Whether an ACP-fronted agent reports usage, and the account-level weekly figure, are not measured here.
- Making the shipped tool list askable without constructing the application is a redesign of the application's bootstrap and is deferred.

Works with jawata-studio 4.4.0.
