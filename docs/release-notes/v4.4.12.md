# jawata-mcp v4.4.12

**The recall calibration gate now asks questions cut from the current store; the engine itself is otherwise unchanged from 4.4.11.**

## What went wrong

- **The calibration gate measured a store that no longer exists.** Its question set named answers from the August 2026 store; none of the 21 right answers is among the 342 accepted rows of today's store, so the gate could pass or fail on rows that were no longer there.

## What changes

- **The gate reads a new question set, `accept-sets-2026-10.json`,** with four questions pointed at current rows (the August file stays as history). Each question is asked in the lane its answer lives in, as the hooks ask, and that lane-by-lane number is the one asserted.
- **Bars set from the first run on a 500-row export of the live store:** lane-by-lane 4 of 4, meaning alone 3 of 4, merged 4 of 4, words alone 4 of 4. Pointing one question at a wrong row turned the assertion red (3 of 4 against 4).

## Known limits

- **Four questions, not twelve.** Two more had only a plausible answer and were left out; two were symbol questions that need described code rows. A larger set needs questions from the person who uses the store, not ones written from rows already read.
- **Asked in its own lane, the no-embedder path also gets 4 of 4,** so these four questions cannot show that meaning adds anything over words; the gate asserts that the combination does not fall below the words-only path.
- **No product code changed.** The version moves so that the engine and the studio ship as one pair.

Works with jawata-studio 4.4.7.
