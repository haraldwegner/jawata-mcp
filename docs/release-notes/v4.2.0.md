# jawata-mcp v4.2.0

Forty-six issues closed, one new refactoring, and every response now says when it is
answering in a degraded state. This is the sprint that went through the tracker rather
than adding to it.

## Every response declares its own degradation

A tool that cannot reach part of what it needs used to answer anyway, correctly shaped and
quietly incomplete — a catalogue namespace missing, a store closed, an embedder absent. The
population was measured rather than guessed: **79 shapes, door by published kind**, and every
one of them now carries a stamp when it is degraded, mirrored by `health_check`. Nine of the
shapes turned out to be defects rather than safe paths and were fixed instead of marked.

The point is not the stamp. It is that an answer which looks complete and is not is the most
expensive thing this product can hand an agent, and it now cannot happen silently.

## New: `data kind=add_record_component`

A record gains a component, and every `new R(...)` across the workspace is rewritten to pass
the new value. By hand that is one edit to the header and as many edits as the record has
users, and missing one is a compile error somebody else finds later.

All three shapes of a record's canonical constructor are handled and told apart, because they
need different edits: implicit (nothing to touch), compact (an empty parameter list, so the
header change suffices), and explicit-full (which must gain the parameter and its assignment).

`change_method_signature` used to refuse this case while pointing at a neighbouring operation
and asserting a cascade that does not happen. It now names the right operation and retracts
the claim.

## The tools

- **`organize_imports` can ADD a missing import** (#16). It could always compute the edit; one
  unset JDT preference meant it never applied it. The published description said the
  capability was unavailable, which had become true by omission.
- **A bare `Type#member` no longer answers for every overload** (#46) — one of them is not the
  answer to the question you asked.
- **`inspect(kind=source)` names the declarer and the file** a symbol actually comes from (#26).
- **Read-only tools are published first** (#22), because truncation is a safety property: when
  a client clips the tool list, what survives should be the half that cannot change anything.
- **The unused-code detector compared binding objects** (#77), so every generic member read as
  dead. It compares keys now.
- **One registry, stamped on every response** (#12, #21, #35), mirrored by `health_check`, so a
  client can tell which build answered it.
- **Impacted-test selection derives symbols from a modified file's diff** (#40), and a rebuilt
  class still selects its tests.
- **`landmarks` answers, and six concurrent callers cost ONE ranking** (#41) rather than six —
  the ranking is O(source types) reference searches, and it used to keep running after every
  caller had given up waiting.

## The knowledge store

Sixteen issues here, and the theme is that the store now distinguishes *no answer* from *an
answer that happens to be empty*: recall tells an absence from a match and says which (#73),
the failure pile records WHEN and not only how often (#74), a configured memory-roots
substrate is authoritative rather than additive (#58), a closed store stops answering (#38),
and a nomination rendered as text answers instead of returning nothing (#61).

## Test infrastructure, which is where the sprint found its own defects

Ten issues, and they share a shape worth naming: a gate that could not fail. An `@AfterAll`
that threw left the counts balanced so every gate on the path passed (#51); a container abort
was invisible both to the count and to the gate policing skips (#54); the abort budget existed,
worked, and nothing called it (#45); the fixture helper leaked every service but the last, and
its own comment had already named that as the flake substrate (#24).

## Removed: sixteen copied modules of our own fork

`org.jawata.core.tests/test-resources` held 16 modules copied out of our java-design-patterns
fork — 123 files — each with a provenance note, policed by 595 lines of machinery enforcing a
third-party boundary against a repository we own and already load.

They were never necessary. The catalogue extractor has always read the fork IN PLACE and
copies nothing, which is this product's one real use of those patterns. The 41 tests deleted
with the slices were not about patterns at all: they used pattern source as a generic supply
of code, and any code would have served.

Of the five defects that corpus is credited with finding, four were already locked by unit
tests. The fifth is restored on a fixture of our own and mutation-proved. **200 files,
14,902 deletions**, and no product behaviour changes.

## Still open

**mcp#18** — `probe_clear` can return SUCCESS while leaving the target's thread suspended. It
is intermittent, it is a debugger-path defect, and its reproduction ships gated behind
`-Djawata.probe.race=true` rather than in the gating suite: a test that reports a known open
issue as a build failure makes every future red ambiguous. The mechanism is not established;
the first hypothesis was refuted by reading the pump, and the current suspect is written down
in the test rather than asserted.

### Gates

Full sharded suite green over the released tree; compile clean at 0 errors and 0 warnings
across four projects. Every fix in this release carries a control: revert it and a named test
goes red.
