# jawata v3.7.1

The Sprint 28 outcome audit's engine-side findings, closed — the release gate
now proves the one path it never exercised, and cannot skip what it claims to
check.

- **The upgrade path has a real fixture.** A store written by the released
  v3.3.1 — old schema, no vectors, none of the counter tables — is committed,
  and the release gate boots the current jar on a copy of it: the old rows
  survive the migration, rows written before embeddings existed earn their
  vectors, an old entry answers a paraphrase sharing no words with it, and the
  counter tables the old install never had are there. Until now every gate row
  entered through the import path and landed at the current schema — the half
  where three of the four v3.4.0 defects lived was never exercised.

- **The build-system cells cannot skip silently.** The PDE (Eclipse plugin)
  dependency-resolution cell used to skip in CI for want of a bundle pool; the
  freshly built dist now serves as the pool and the job fails on any skipped
  cell, Gradle and PDE alike.

- **Every gate check is named after the promise it protects** — no more
  sprint-number labels whose meaning evaporates two sprints later — and the
  "tool count is still 45" sentence finally has a live check behind it.

Full gate on this build: 43 checks, 0 failed.
