# jawata-mcp v4.4.9

**`tools/list` now says, per tool, whether a call changes code, so a client keeps no list of its own.**

## What went wrong

- **No client could ask the engine "did this call change code?".** The annotations the engine published cannot answer it: `readOnlyHint` is false for `compile_workspace`, `run_tests`, `experience` and `hire`, which change no source, and `destructiveHint` is absent for `format`, `quick_fix`, `refactoring` and `dependency`, which do. The studio's hook therefore kept three hand-written lists of code-changing tool names. They disagreed with each other and with the engine, named four tools the engine had retired, and left out `data`, `hierarchy`, `delete_anonymous_implementation` and `dependency`.

## What changes

- **Every tool in `tools/list` carries `_meta."jawata/changesCode"`, a boolean.** It is the engine's own `Tool.changesCode()`, the flag a hired run's calls are already classified by, so there is no second list in the engine either. It sits in `_meta`, the extension point the protocol reserves, so a client that validates `annotations` strictly sees no new key. 17 of the 44 tools answer true: `apply_cleanup`, `apply_null_annotations`, `change_method_signature`, `data`, `delete_anonymous_implementation`, `dependency`, `extract`, `format`, `generate`, `hierarchy`, `inline`, `move`, `organize_imports`, `quick_fix`, `refactor_to_pattern`, `refactoring` and `rename_symbol`.
- **A test publishes every shipped tool and checks each one's flag equals its own answer,** and names the five the annotations got wrong or left silent (`format`, `quick_fix`, `refactoring`, `dependency` true; `compile_workspace`, `run_tests`, `experience`, `hire` false). Before the change 0 of 44 listed tools carried `_meta`.

## Known limits

- **The flag is per tool, not per action,** and errs toward true: `refactoring(action=inspect)` only reads and answers true, because the same tool writes on another action. This is the engine's own rule for the flag (a tool that can write on one action and reads on another says true, so a measure over-reports rather than under-reports). A client that needs the action-level answer still has to read the call's arguments.
- **A client that validates `_meta` strictly was not measured.** The field is named under the `jawata/` prefix the protocol asks vendors to use.

Works with jawata-studio 4.4.4, which reads the flag to generate its hook's list.

## Also in 4.4.9: a hired run is scored, and an abort under a mutation is its own signal

- **A hire of a seat that declares `changes_code: true` runs in the brain's write-capable mode; every other seat stays read-only.** Until now every Claude hire ran `--permission-mode plan`, so a worker could not change code. The key is read strictly (`true` or `false`) and is refused on a brain whose dialect cannot carry it (copilot, codex, script). A seat that does not declare it loses every code-changing tool of the resident, even one its tool list names.
- **A hire's answer carries the worker's measure and the PM's.** `shareThroughTools` is the share of code changes made through an engine tool against by the brain CLI's own editors ("NO CODE CHANGE MADE" when none, never 0 or 1); `tokens` are read from the brain's own final event ("NOT REPORTED BY THIS BRAIN", never 0); `instructionsFrom=<plan>` scores a worker against the INSTRUCTION blocks of the PM's or chief engineer's answer: how many ran as written (one tool, one call, the arguments written) and the issuer's tokens per instruction that did. A call to a tool the CLI never offered is neither rework nor an extra change.
- **`run_tests(action=coverage_mutation)` reports a test that aborts under a mutation as its own kind of kill.** PIT counts an aborted test (a failed assumption) as a pass, so the mutation came back as a survivor. A new tools jar, `org.jawata.pitplugin`, is PIT's JUnit 5 plugin where a test that passed before a mutation and aborts under it is a failure under a marked name. The answer has `summary.abortConverted` and `abortConversions` rows (symbol, line, mutator, description, aborting test), and `errorCount` is survivors plus abort conversions. A test that aborts with no mutation at all is not blamed on one.

### Known limits (this part)

- The test named in an abort conversion is the first to reject the mutation; another test may also have failed it.
- The abort baseline is recorded while PIT discovers tests; a project whose tests PIT cannot run at all gets no result, as before.

## Also in 4.4.9: a recall names its lane, and each lane is searched on its own

- **A `recall` or `nominate` call that names no lane is refused, with the list of lanes in the refusal.** This changes what a client must send. The engine no longer derives a scope for anyone: the call names one or more lanes (`experience`, `domain`, `rules`, `code`, `patterns`, `transcript`, or `all`) or, new in this release, an `occasion` (see below). Studio 4.4.4 names its lanes; a client older than that gets the refusal.
- **Each lane is scored, ranked and cut on its own.** A lane's word rarity, meaning scan, shortlist and cap are its own, the after-search lane filter is gone, and every answer says how many rows each searched lane held (`scanned`). A lesson is never ranked against, or pushed out by, a row of another lane. The catalogue's patterns have their own lane; hazards and seat runs sit in the experience lane.
- **The `transcript` lane stores what was said in a session,** as compressed turns with a database word index, and answers `check` (found, not found, could not check) for words he wrote. It is named like any other lane and is never part of `all`. It can be switched off, and then it holds no rows.
- **Another workspace's rows no longer answer here.** The workspace rule is written once, on the lane, and holds on the keyword path and the analogy path of a recall: a symbol cue no longer returns another workspace's code row, `scanned` counts the rows that answer here, and a recall that held rows back says how many. The describe path and the job write gate are this workspace's too: another workspace's same-named job is no longer reported as held and is never overwritten by your description. A writer with no workspace identity is refused as ambiguous once two workspaces described one member.
- **`experience` accepts an `occasion` instead of a lane list** (`typed_message`, `tool_call`, `recall_gate`, `after_compaction`, `design_question`, `does_it_exist`). The engine owns which lanes each occasion asks. Naming an occasion beside `lane` or `lanes` is refused; the name is read without regard to case or spacing, and a blank one falls back to the lane form.
- **The map a task opens with carries the area of every package it shows a member of,** up to 16 rows, with the embedder off as well. Before, whether an area was listed was decided by row-id order. The list keeps the ranked rows first and marks the added areas `added`; the rendered map prints areas before members.

## Also in 4.4.9: a backup copy that disagrees with itself is not kept

- **A copy taken while another connection committed could come back with a row count one too high.** Measured with the embedder off: 14 of 40 plain copies; compacting the bad copy repaired 0 of 14. Nothing was lost (all rows read), but the count was wrong and survived reopening.
- **The writers are now paused while a copy is taken, and every copy is checked.** The copy is unpacked and opened on its own and its count is compared with the rows that read. A copy that is not a readable zip, that H2 cannot open, or whose count disagrees is deleted. Paused: 0 of 24 bad in the final run (3 of 16 before). The daily copy is tried again by the hourly check, with no cap. The copy before `wipe`, `prune`, `import`, `delete` or `restore` gets 3 attempts; if none is clean the operation is refused and the answer names `proceed_without_clean_backup=true` as the way to go on. A copy that cannot be WRITTEN (a full disk) keeps the old rule: logged, and the operation proceeds.
- **Known limits.** The pause was measured on a 224 MB store with 20,000 rows (copy 1.7 s, check 0.8 s), not on a ~90 MB store or against the other engines' 10 s lock timeout. A new connection during the pause is refused at once and the open retries it. The case of a zip stream cut short inside a valid zip has no test of its own.

## Also in 4.4.9: seats

- **A seat can declare `reads_files: true`** and its hire is offered Read, Glob and Grep and no writing built-in; any other built-in name is refused. A seat file's switches (`changes_code`, `reads_files`, `accepts_uncontained_writes` and the others) are read by one strict reader, so a misspelled one is refused instead of silently off.
