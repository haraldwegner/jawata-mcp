# jawata-mcp v4.3.3

**Memory answers take tens of milliseconds instead of a second and a half, and accepting an entry
writes its story file.**

## What went wrong

- **Every memory question read the whole store.** With 10,257 entries a question took 1.5 to
  1.6 seconds. A profile put 61% of that time in reading every row from the database, and 18% in
  rebuilding the word index from those rows — on every question, although the rows change only
  when something writes. The hooks give a question 1.2 seconds, so many answers arrived as "store
  unavailable" or not at all, and studio's Reporting screen marked the store "too slow to use".
- **Accepting an entry wrote no story file.** The file was written only when the engine was
  started with a story folder set, and no engine studio starts sets one. So an acceptance that
  `/memorize` says writes the file wrote nothing, and nothing said so.

## What changes

- **The store is held in memory and read again only when it changed.** Each question asks the
  database one cheap question — has anything been written? — and reuses the entries, the word
  index and the meaning vectors when nothing has. Measured on the same 10,257-entry store, median
  per question: 61 ms for a question in words (was 1,530 ms), 140 ms for a symbol (was 1,604 ms),
  49 ms for a question that matches nothing (was 1,471 ms).
- **A decision reads only the entries it chose**, instead of the whole store.
- **An accepted entry's story file goes into the store's own story folder** when no folder is set
  — the folder its stories are loaded from. Setting the folder to `off` writes no files.
- **The file is tied to its entry**, so the next load of the folder updates that entry instead of
  adding it a second time. An entry that was loaded from a file already has its file: accepting
  it writes no second one and leaves it tied to its own.

Works with jawata-studio 4.3.4, whose settings describe the new story folder default.
