# jawata-mcp v4.1.1

Five fixes, every one found by using v4.1.0 on real code rather than on its own tests —
this repository's own 1056 sources, and the platform matrix at the v4.1.0 tag.

## A finding's fix can now be pointed at the thing it found

**Message Chains handed over a method and needed a position.** The finding named the
enclosing method, qualified, which every other routed fix resolves. Hide Delegate does not:
it acts on ONE chain and a method may hold several, so it answered *"no two-deep call chain
at that position"* about a chain the detector had been looking straight at. It was emitting
the literal `-1` for its column while holding the node's offset, and a line without a column
is not a position — so the rendered fix carried no coordinates at all. It now emits the
chain's own column.

**Feature Envy named destinations the move cannot accept.** A method was reported as envying
a type, and `move kind=method` — the operation the message itself names — answered with four
possible targets, none of them the one named. That door moves a method onto the type of a
parameter or a field; the method in question did not hold that type, it constructed one and
returned it. Counting accesses says a method leans on another type; it does not say the
method can go there, and those are different claims. The detector now proposes only a type it
can actually reach.

## A slow detector has the same way out a slow family always had

Ask for a whole family of checks and the product refuses in milliseconds, handing back the
asynchronous form. Ask for one slow check and it burned the caller's timeout with no sweepId,
no instruction, and nothing to do next — a bare timeout cannot be told apart from a broken
tool, and the two moves it leaves are to retry for the identical result or to abandon the
tool. Measured: one check over 1056 files timed out twice at the 30-second default and
answered 228 findings inside a family sweep, so the work was always finishable and only the
channel was missing.

`action=start` now takes a single `kind` as well as a `family`, the status response says
which it is running, and the family refusal no longer promises that single checks always
finish in time — it did not, and that sentence was the one sending callers down the path
with no exit.

## A refusal about a file the product just wrote now says what it wrote

The compile gate skips everything but syntax in a CREATED file, on the reasoning that its
validity is proven by the modified files that reference it, "which do resolve them". On the
macOS job at the v4.1.0 tag that sentence did not hold: a file is on disk before the Java
model knows it, and a modified file re-parsed in that window resolves the new type to
nothing. The gate then refused a correct refactoring and undid it, reporting a missing type
and nothing whatever about the file meant to declare it — which is gone a moment later, so
the question could not be answered afterwards at any price.

Two changes. The model is settled for the files a change touched before their errors are
read, which can only ever give the compiler more of what is genuinely on disk. And a refusal
now carries each created file's package and imports, read while they still exist — the two
lines that decide whether a same-package type resolves.

## Recorded parity comparisons stop failing on a line-ending convention

One recorded comparison diverged on Windows by line endings alone. The checkout was measured
not to be the cause — the repository has pinned endings since the first Windows run failed
nineteen of these, and no stored file carries carriage returns — so the inputs were already
normalised and the output of one engine was not. Both sides of the comparison now have the
convention taken off, which is a no-op where they already agree and cannot make a differing
result match: a genuine content change still fails, and there is a test that proves it.

### What is unchanged, and said plainly

The macOS settling fix has no test, and cannot honestly have one here: the timing window it
closes does not open on Linux, so any assertion written for it would pass before the fix as
well as after. Its control is the next macOS run.
