# jawata-mcp v4.6.15

**An Antigravity (`agy`) principal reaches the chat's engine through a small stdio program, a chat's principal is told to end its turn after a hire and not to wait for it, and a hire by an Antigravity principal draws a card that says why when it was refused.** Needs jawata-studio 4.6.19 and jawata-chat 0.2.15.

## What changes

- **Antigravity as the chat's principal.** `agy` cannot attach an HTTP tool server, so its calls went to its own configuration and never reached the engine. The engine now hands such a brain `java -jar jawata.jar --mcp`, a stdio program that forwards every call to the engine of that chat (so the engine knows whose calls they are). A line of the brain's reader holds about 60 000 characters and the tool list is far longer, so the list is served in pages, and an answer too long for a line is cut with a sentence that says so.
- **All 51 tools are offered to it.** Measured on `agy` 1.5.15: it offers its model the smallest tool definitions first, up to about 62 000 characters in all, and answers *tool X is not enabled* for the rest. A `tools/list` request can now name a limit for one definition and a total for all of them; every definition is first made as small as it can be **without leaving a parameter out** (that brain refuses an argument the schema does not name), and the spare room goes to the principal's tools first (`hire`, `hire_wait`, `experience`, `files`, `lookup`, `git`, `plan_steps`, `plan_board`, `brains`, `health_check`). The bridge asks only for the tools the brain's seat may call.
- **Its permission titles are read.** `Run mcp_<server>_<tool>` and `MCP Tool <tool>` name the engine's tool, so a seat's list answers them and an engine call is not withheld as the brain's own command.
- **A hire by an Antigravity principal draws a card**, and a refused one ends as `refused` with the engine's own reason (before, no card was drawn at all).
- **A chat's principal does not wait for its hires.** The answer of `hire` told every caller to call `hire_wait`; for the one caller whose report comes back as a new turn (a chat's principal) it now says *end your turn now … do not call hire_wait*, and `hire_wait` answers at once for it. For any other client nothing changes. Main's seat says it never waits for a hire and never hires the test manager itself (the pm does).

## Known limits

- **A hired Antigravity's calls are counted as other calls, not jawata calls,** on the hire's card (3 of 3 in one run, against 20 jawata calls for the same hire on Claude): the counter does not read Antigravity's tool titles. Open.
- Shown in a real chat window under a virtual display against a sandbox engine, with Antigravity and with Claude as the principal: a refused hire, and a message answered 1.2 s after it was typed while a pm hire ran for 86 s. **Not shown:** a hire that runs for several minutes, and the studio's own window and engine.
- The stdio program's serial loop and its check that a server name begins with `jawata` are known limits, not changed here.
- Windows and macOS are run by CI, not by hand.
