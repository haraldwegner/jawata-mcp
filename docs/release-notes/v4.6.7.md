# jawata-mcp v4.6.7

**The chat's buttons stay usable while a job runs, a hire you stop is announced, and the engine carries the seats and the settings the studio's new pages read.**

4.6.7 contains everything on main after 4.6.5, including the changes of 4.6.6 (which was built from a side branch). 4.6.6 changed the principal's brain row; that is in this release too.

## What changes

- **Picking a model, pressing Stop or switching autocontinue while a long job runs no longer waits for the job.** Measured on 4.6.6 with a stand-in agent: a model picked while a turn ran held the engine's session lock until the turn ended, and Stop and the option list needed the same lock, so all three stood still. The pick is now kept for the next message. A new test fails on 4.6.6 and passes here. Not reproduced in a real chat window by hand; the freeze he saw after killing VS Code is not explained by this change.
- **A message the person types while autocontinue is on ends it.** The button and a typed `/autocontinue` are one state; `/autocontinue-off` is the same ending, named. The agent no longer moves on while the person is talking to it.
- **A hire the person stops, or that ends in an error after its plan opened, is announced under its own plan id and name,** so its card ends and its lead is told. Before, it was announced with no plan, which nothing could match.
- **A slow write of a finished turn to the shared transcript lane can no longer hold the chat on "working".** The engine writes it on its own thread and holds the answer back for it up to five seconds; a write that takes a second or more is counted and logged with its time. This is a hypothesis for one stuck turn, not a proven cause of it.
- **The engine carries the 20 seat files of the studio** (jawata-studio 2698ea5) and hires a seat by name from them; a seat file given by path, a seat switched off and a seat nothing seals are refused before a brain starts.
- **A seats door and a settings screen for a host:** each seat's command, purpose, on or off, brain and place in the workflow; the brains the machine has and their models (asked of each agent program once and kept); the six memory settings on a screen of their own with the words and on-or-off kind a host shows.
- **The principal's brain row names the brain you picked alone until its own session opens** (4.6.6), and a hired agent's prompt no longer sends an options update to the chat.
- **The document writer refuses text that tells an agent what it may do, and a release is ordered only by `/release` or the bare word,** never by a sentence that mentions it. A hire stopped by its ceiling records its step as did-not-answer, not as one error answered.
- **The README names all 50 published tools** (brains, files, git and lookup were missing).

## Known limits

- Checked on Linux, in sandbox engines with stand-in agents and with Claude Code's adapter and Cursor's agent as real brains where noted. Windows and macOS builds are produced and checked by this release's CI run, not by hand.
- The turn of a chat that is closed keeps running in the engine; whether closing the chat should stop it is not decided.
- A Cursor principal runs in Cursor's "ask" mode, which hides jawata's tools, so it cannot hire. The decision on how to bound Cursor's own writes is still open.
- The engine publishes files, lookup, git and brains to every client, and `git` release works only for the studio's principal; there is no per-client tool list yet.
- A hire that ends normally with no change still shows its step as passed, and each flagged worker step starts its own observer hire.
- A release is ordered only by `/release` or the bare word `release` (with at most "please", "it", "now" and a version), never by a sentence that mentions it.
