# jawata-mcp v4.5.2

**A hired agent's rejected proposal puts back the files it changed wherever that is exact, a hired agent that may use the shell is refused a text search over Java source, the engine's own take-back no longer shows up as a second step in Eclipse's Undo list, and the hire tree follows the seat files.**

This is a patch release on 4.5.1. The tool list is unchanged (still 46 tools); what changed is how the engine behaves when it directs agents and when an editor hosts it.

## What you can do now that you could not before

- **Reject a hire's proposal and get the files back.** When you reject a proposal, the engine puts back the files the hire changed to what they were when it began, wherever that is exact: a tracked file that was clean before the hire and still holds what the hire left is restored by `git checkout HEAD -- <path>` (so its bytes are exactly those of HEAD), and a file the hire created is deleted. Every other file is kept and named on the card with its reason: a file that held your own earlier edit, a file someone changed after the hire, a file too large to carry, and every file when the folder the hire ran in is not known. The take-back is built on git and not on the hire's undo handle, because most hires edit with their agent's own tools, which leave no handle.
- **See who hires whom from the seat files.** The tree of seats (a seat's place, its role and the seat it escalates to) is read from the seat files over the signed tree. A file that is wrong is refused as a whole with the engine's reasons, and the signed tree is used instead.
- **See a hired agent compact its context.** A hired agent that is compacting its context shows as compacting (the signal was measured on the Claude adapter only).

## Behaviour changes

- A hired agent that may use the shell is still refused a text search over Java source when the engine answers its permission request. The refusal names the tools that answer the question; a build, a search over other files and a declared fallback pass.
- The engine's own take-back of a kept change is performed in its own write mode (UNDO), which an editor with an undo history keeps off its list. Before, Eclipse listed the take-back as a second step beside the one it undid.
- The debug agent and the recording flag a program is started with are written once, on the host port, and the engine's dev/sim preset reads them from there. A test holds the preset equal to the port, so an editor plug-in can take both from the port instead of repeating them.

## Known limits

- **The take-back puts back only what is exact.** A file that cannot be put back exactly stays as the hire left it and is named; the engine never overwrites your own edit.
- **Checked on Linux only.** Not run on Windows or macOS, as in 4.5.1.
- **The compacting signal** is measured on the Claude adapter; another agent that does not send it shows no compacting state.
