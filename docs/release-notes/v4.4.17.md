# jawata-mcp v4.4.17

**The `profile` and `debug` artifact listings come in pages instead of one 5 MB answer, a sibling lookup that reached no sibling no longer says none holds the type, and `run_tests` drops DEBUG lines on Windows too.**

These came from running 4.4.16 on this project's own workspaces and the design-patterns workspace.

## What went wrong

- **`profile(action=artifacts)` and `debug(action=artifacts)` listed every stored artifact in one answer.** After a week of hired runs the store held 1,972, and the answer was 4.97 MB, more than a client accepts.
- **A lookup that no sibling answered said "No sibling workspace holds it."** The siblings had not spoken: a resident that is still starting, or a stale registry row, answers nothing, and the sentence claimed more than that.
- **`find_field_writes` counted a match that is in no source file as a write.** The row had no line and no column, and its path was the project's own folder.
- **The `run_tests` output tail kept DEBUG lines that end in a carriage return**, which is how a Windows JVM prints them. 4.4.16's filter did not match them.
- **A staged change that creates a file showed nothing for it.** An extracted interface or a generated enum has no old text to compare, so the diff read as empty, as if the change did nothing.
- **`apply_null_annotations` staged a clean diff for an annotation the project cannot resolve.** Applying it was undone by the compile check, but the staged diff gave no warning.
- **`quick_fix` with `action=list` was described as needing only a file path.** It also needs `line`.

## What changes

- **The artifact listing is ordered by when each artifact was made, newest first.** It was ordered by name, which starts with the kind, so every flight recording came before every heap dump however old, and a new heap dump sat behind all the recordings. It is also a page: `offset` and `limit` page it (default 10, at most 25). The answer carries `count` (all the store holds), `returned`, `offset`, `limit` and `hasMore`, so a short page is not read as the whole store.
- **A lookup no sibling answered says "No sibling workspace answered."** One that some siblings answered says "No sibling workspace that answered holds it." The claim "none holds it" is made only when every listed sibling replied.
- **`find_field_writes` skips a match that has no source file.**
- **The output tail filter reads lines that end in a carriage return.**
- **A staged answer names the files it creates or moves that the diff cannot show** (`filesNotInDiff`), and says why.
- **`apply_null_annotations` refuses, staged or not, when the project cannot resolve the annotation** (`NULLNESS_ANNOTATION_NOT_ON_CLASSPATH`), and says to add the library or pass `style` naming a family the project has.
- **The `quick_fix` description says `list` needs `filePath` and `line`.**
- **The release gate runs the end-to-end check of the built distribution** (`build/28k-e2e.sh`: `tools/list` against its golden byte for byte, and the front-door promises P0 to P8). It was run by hand at the checkpoint and by nothing at the release.

Each change except the last two has a test that fails without it.

## Behaviour changes

- **The artifact listing no longer returns every artifact.** A caller that read the whole `artifacts` array must page, or read `hasMore`.
- **`apply_null_annotations` refuses where it used to stage.** With no annotation library on the project's classpath, `kind=add` now answers `NULLNESS_ANNOTATION_NOT_ON_CLASSPATH`.

## Known limits

- **`data kind=encapsulate_field` writes its generated accessors with tab indentation into a space-indented file.** They compile. The indentation comes from JDT's own formatter default, and matching the file would mean changing the project's formatter setting, which a tool must not do.
- **On Windows, a path given in short-name form (for example `C:\Users\RUNNER~1\...`) is not matched to the project loaded under its long name.** The fix is planned for the OS-coverage sprint.
- **`CoverageService` and `MutationService` still import the Java provider's jar locator**, so the coverage and mutation tools are not yet independent of the Java provider's package.

Works with jawata-studio 4.4.9.
