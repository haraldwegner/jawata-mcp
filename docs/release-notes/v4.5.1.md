# jawata-mcp v4.5.1

**The engine can now ask your editor to run the program you already set up, checks a change against your editor's refusal before it writes anything, starts test and debug JVMs on the runtime your editor says the project uses, and no longer lets a change it takes back show up in your Undo list.**

This is a patch release on 4.5.0. The tool list is unchanged (still 46 tools); what changed is how the engine behaves inside an editor that hosts it, and one new parameter on `debug`.

## What you can do now that you could not before

- **Debug the program from your own run configuration.** In an editor that runs programs for jawata (Eclipse is the one this was built for), `debug` with `action=launch` and `configuration=<name of your run configuration>` asks the editor to run it with the debug agent and then attaches. Your configuration is never changed; the editor starts a working copy. The program is already running when the agent attaches, so reproduce the problem in it first, then set breakpoints or probes.
- **See which programs were started for jawata.** `debug` with `action=discover` now marks each program the editor started for jawata, with the configuration it came from and who started it (the agent or you, through "Run for jawata"), so the agent attaches to the right one by process id.
- **A refused write is an answer, not damage.** Before any change is written, the engine asks the editor whether it will write over those files at all. If the editor refuses, nothing is written and the answer carries the editor's reason. Before this, the engine wrote first and found out afterwards.
- **One place chooses the Java runtime for a child JVM.** A test run, a mutation run and a debug launch each start a JVM for a project. They now ask one place, by the project's name, which runtime to use; the editor's answer for that project wins, and without one the engine's own runtime is used, as before. Nothing else in the engine reads `java.home` any more, and a test fails the build if something does.
- **Every setting says who it is for.** Each setting is marked as meant for the person, set by the launcher, or an internal measurement switch. An editor's settings screen can show you only the first kind. The sentence about an environment variable (such as `JAWATA_TIMEOUT_SECONDS`) is now added only for the engine that runs on its own, since an editor has no such variable.
- **A trial change you accepted is kept once; a refused one never reaches Undo.** The engine applies a change as a trial, judges it with the compile check, and only then asks the editor to keep it. An accepted change becomes one ordinary step in Edit > Undo; a change the check refuses and takes back leaves no step behind.

## Behaviour changes

- A change is now applied forward as a trial and kept after the check passes. In an editor with its own undo history that changes what Edit > Undo lists (one step per accepted change, none for a refused one). In the engine that runs alone there is no such history and nothing differs.
- A setting key that names no audience is refused as soon as it is declared (the engine will not load it), so a new setting cannot reach a settings screen unclassified.
- The profiler's `jcmd` and the native-crash tool's `java` still use the engine's own runtime: they are not a launch of a project's JVM and name no project.

## Known limits

- **Checked against the stand-in editor only.** The new behaviour is covered by tests that use the engine's fake host. Only an editor-side implementation of the run, refusal, runtime and keep ports makes any of it visible, and that side lives outside this repository. In an editor that has none of them the engine behaves as in 4.5.0, apart from the settings wording above.
- **The run port has two verbs.** The engine can ask for a run and list running programs. Running a plug-in test through the editor's launches is in the design and not built.
- **A program started this way is not held at its first instruction.** You cannot arm a breakpoint before it starts; reproduce, then arm.
- **If the editor cannot keep an accepted change** (the keep call answers false), the change stands and the engine's own undo still holds it, but it will not appear in Edit > Undo; the engine logs a warning.
- **Not run on Windows or macOS**, as in 4.5.0.
