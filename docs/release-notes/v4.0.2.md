## jawata-mcp v4.0.2

**A finding no longer names one refactoring and offers a different one.** Found
by dogfooding v4.0.1 on release day, with a single call against real code: asked
about a switch statement, jawata answered with prose recommending *Replace
Conditional with Polymorphism* and a runnable instruction offering *Refactor to
State*. Two answers in one sentence, and no way for a reader to tell which was
meant.

The two halves come from different places. Each detector carries its own
recommendation sentence, hardcoded when the detector was written; `CureCatalog`
separately resolves the runnable operation and its catalogue address. Until
v4.0.0 threaded the store through every detector, only one kind rendered the
second half — so the two were never seen side by side and could disagree
unnoticed.

**Sprint 28d built the operation the prose was asking for, and nothing pointed at
it.** `replace_conditional_with_polymorphism` and
`replace_constructor_with_factory` shipped in that sprint and were referenced by
no cure at all. They existed, were registered, were tested, and could be run by
hand — reachable only by someone reading the tool list. Built, not wired: the
same shape that shipped v3.4.0's central feature inert past 1591 passing tests.

Now `switch_statements` offers Replace Conditional with Polymorphism first, which
is what its own prose names. State keeps its place as a second route, because a
switch on an int state field genuinely is a State candidate and the two are not
rivals; order is the claim. `type_code` gains Replace Constructor with Factory
Method as a second route.

Both catalogue keys were checked to resolve to live entries before being wired.
Composing an address that does not resolve is precisely the failure `CureLookup`
exists to prevent — a cure naming a design the store does not hold reads exactly
like one it does.

**The check nobody had written.** Three parts, in
`TheProseAndTheCureNameTheSameFixTest`: the first runnable cure must be the one
the detector's prose names; every shipped operation must be reachable from a
problem that recommends it; and a control that fails against the v4.0.1 table, so
the comparison is proven able to disagree rather than only ever seen agreeing.

Nothing existing could have caught this. The cure tests assert that a declaring
kind renders a cure carrying a tier, which this did. The hollow-wiring gate asks
whether a member has a caller outside the tests, and these operations do. No
check asked whether a shipped operation is reachable from the problem that
recommends it.

Two corrections to numbers stated in v4.0.1's own release notes and commit
messages: **eleven** smell kinds declare a cure, not twelve — the commit
message's own list adds to eleven — and **seven** of them offer a runnable
operation, not four; three kinds share one table entry. The remaining four are
advisory by design: they name a design to read, with nothing to run.

Sharded suite on a clean build: 2248 total, **0 failed**, 2 corpus-gated skips.

**Four guards refused the first attempt at this fix, and all four were right.** The
migration guard pinning what a deleted table held; the count of declared catalogue
keys; the tier control, which removes a step from the registry by name; and the
open/closed detector, which relabels these findings. Each is updated with its
reason rather than silenced.

That is worth more than the fix. One fact — which refactoring this kind
recommends — was pinned independently in four test files, each holding the
literal on its own. A fact asserted in four places is a fact that can be
corrected in three, and the fourth then contradicts the product while its own
test still passes. It is the same shape as the defect above: the prose and the
table each kept their own copy of what to recommend, and drifted.
