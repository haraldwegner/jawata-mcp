# jawata-mcp v4.4.10

**Accepted rules reach the agent, the store lookup on every response stops timing out at ten thousand rows, and a seat that writes only the knowledge store can run.**

## What went wrong

- **A rule he accepted reached no one.** The rules lane existed and nothing asked it: a typed message asked the lessons only, and a hired seat's brief carried the seat's own text and no rule.
- **The prior-work lookup on every response was thrown away at ten thousand rows.** Measured on a synthetic store of 10,189 rows with the embedder and the vector module on: the lookup is a four-lane recall (experience, domain, rules, code) and costs 234 ms at the median, 276 ms at the 90th percentile and 414 ms at the worst against a 200 ms budget. 36 to 40 of 40 writes that named a symbol came back saying "the store did not answer within 200ms; it is unreachable or wedged", and the caller had waited the 200 ms for nothing. It was not a write queue: a burst of 40 writes and the same 40 spaced apart cost the same, and a write with no symbol (so no lookup) took 126 ms and never said it.
- **A hired seat whose job is to write the store could not read or write it.** Every seat that does not change code is hired in Claude's plan mode, and plan mode refuses the `experience` tool for every kind, reads included. The first real hire of the new rottenmeier seat read none of his turns and wrote no rule; a one-call hire of the cataloguer was refused with "Cannot call mcp__jawata__experience while in plan mode".
- **`experience(kind=list, lane=rules)` returned lessons.** The door accepted `lane` and read it nowhere.
- **The stop check that asks which members a turn left undescribed asked about every method of every file the turn touched.** A one-line edit to a class of twenty tests demanded twenty-three descriptions.
- **The hollow-wiring gate failed after a version bump without saying what to do.** The engine's refusal ("Maven dependency resolution failed") was printed; the install step that cures it was not.

## What changes

- **The rules lane is asked.** A typed message (occasion `typed_message`) now asks the experience lane and the rules lane, so an accepted rule whose situation the message names is injected. A new occasion `lesson_lookup` asks the lessons alone. A hired seat's brief carries the accepted rules that bind it: those labelled `seat:<name>`, those labelled with an activity the seat declares (`activities:` in the seat file, for example `release`), and those labelled for no seat. A rule recorded after the build reaches the next brief with no code change.
- **A rule is proposed, then accepted.** `promote_rule` takes `status=candidate` (default `accepted`); a candidate requires an `operation` label and a `situation` and is never injected. `operation=all` binds every seat. `experience(kind=review_sweep, seats=<directory>)` lists the labels no seat file asks for (`rulesNobodyAsks`), so a mistyped label is reported and not silent.
- **`-Djawata.rules.limit=N`** caps the rules in one brief. Unset means every binding rule, which is the default; a value that is not a positive number leaves the cap off.
- **The lookup on every response buys 400 ms** (`ToolRegistry.STEERING_BUDGET_MILLIS`) instead of the store's 200 ms floor, which is unchanged for every other caller. Same probe afterwards: writes that named a symbol said "no answer" 0 of 40 times in every phase, for about 40 ms more per call at this size. A store that never returns now costs a call 200 ms more than before. The reason text no longer says "unreachable or wedged"; it says what was observed and that the cause is not known.
- **A seat can declare `writes_store: true`.** It is hired outside plan mode, with every code-changing tool still hidden and none of the CLI's own file tools offered. Read strictly, refused on a brain whose dialect has no such mode (copilot, codex, script) and beside `changes_code`. The rottenmeier and cataloguer seats of studio 4.4.5 declare it; after it the rottenmeier hire saved 7 candidate rules and the cataloguer's one-call hire was answered.
- **`experience(kind=list)` honours `lane`, `lanes` and `occasion`.** The filter runs over the whole listing and then the limit, so a named lane is not answered with a page already cut to other lanes.
- **`describe(action=jobs_for)` accepts `changedLines`:** an object from a file path to `[first, last]` line pairs (1-based, inclusive). Only the methods those lines fall in, their Javadoc included, are asked about. No entry or an empty list asks about the whole file, as before; lines in no method are refused and not answered with an empty list.
- **Build:** the runner prints a failed test when it fails; a skip-wording gate reads every skip message against the abort budgets and CI runs it first; `build/release-gate.sh` runs what CI runs (that gate, a clean install, the suite with the embedder on and with it off); the hollow-wiring gate's refusal after a version bump names `mvn -B -f build/pom.xml install -DskipTests`.

## Known limits

- **The latency numbers are from a synthetic store** on one machine at a load of 2.5 of 20 cores. His real store and a loaded machine were not measured. The 400 ms is one constant and reverts in one line.
- **`changedLines` takes effect only with studio 4.4.5.** An older hook does not send it and the whole file is asked about, as before. Files changed through the refactoring tools were never in the hook's list and still are not.
- **Seven shipped seats that declare `experience` (main, ux, debugger, test-manager, chief-engineer, pm, architect) are inferred to have the same plan-mode blind spot and were not changed.** Only rottenmeier and cataloguer were measured. Switching one changes what its earlier hires measured (the test-manager would also gain `run_tests`).
- **A rule's `operation` label is matched exactly.** A label no seat file asks for binds nobody; the review sweep reports it but nothing refuses it at write time.

Works with jawata-studio 4.4.5.
