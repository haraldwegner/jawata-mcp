# jawata-mcp v4.6.11

**A client without the jawata chat collects a hire's report itself, a hire that goes quiet is told to you, and who may hire and who may run tests is decided by the seat the engine knows the caller to be.** This release is what jawata-studio 4.6.15 and jawata-chat 0.2.11 need.

## What changes

- **`hire_wait` collects a hire's report** for a client that has no jawata chat (Claude Code, Cursor and the like). `hire` answers at once with a hire id; `hire_wait` answers the hire's state, waits up to 50 seconds for a running one, and hands the report over once as new, then as already read.
- **A hire that goes quiet is noticed.** Past a first ceiling (`jawata.hire.stallSeconds`, 300 seconds by default) the hire's card reads *stalled*, `hire_wait` says so, and the principal's brain is given a turn naming it. Past a second ceiling (`jawata.hire.stallStopSeconds`, 1200 by default, 0 switches it off) the engine stops the hire and answers it as a stall, with the seconds, not as a stop by the person.
- **A session the engine cannot place may only hire as `main`.** A plain client is a guest; a hired brain is placed by the plan id it presents in the session header or the URL. A hire whose named hirer is not the seat making the call is refused.
- **A full test run is the test manager's decision.** `run_tests` with `fullRun` is refused from any other seat and from the test manager without a `reason`; a package-wide run is refused from a developer's, a chief engineer's or a pm's session. The reason is repeated in the run's answer and carried in the hire's answer as `fullRunReasons`.
- **A hire or a test run is refused when the machine has too little memory** (less than 1024 MB for a hire, 512 MB for a test run), naming the figure. The figure is read from `/proc/meminfo`, so off Linux nothing is checked.
- **One pm runs a sprint.** A second pm for the same plan file is refused naming the first, and a pm hired with no plan file is refused.
- **Hires started in the background run on virtual threads** of the engine instead of a pool of platform threads.
- **Seats and cards.** The sealed seats equal the studio's again (the test manager carries the dogfood duty after a release). A running hire's card shows the brain and model the Seats page stores for the seat, and the menu lists each model a brain offers.
- **A file no loaded project holds is answered once, by what is true,** by the move, hierarchy, data, change-signature, `find_references`, `find_field_writes`, `get_at_position`, `go_to_definition` and `rename_symbol` doors, as the analyze and generate doors already did.
- **A refresh re-derives each project's model** as a fresh add does: library jars of another version and source folders added after the load are picked up.
- **A shell instruction runs as written** when the worker runs its command through the guard's bracket, and a shell call Claude's adapter opens under its own description is named `Bash`.
- **Smaller:** `plan_steps` names the session that opened each plan and can list every session's; the hire's answer names the search path its brain was started with; the README lists `hire_wait` and counts 51 tools.

## Known limits

- Shown over the wire on a throwaway engine with stand-in hired brains, and by a real Claude Code session and a real Cursor agent each collecting a hire's report with `hire_wait` (a 19 second wait). **Not yet shown:** a hire that outlasts a client's own tool timeout (Cursor gave up on a 109 second call once), and a real hired agent making the full-test-run call itself. Both are the first dogfood run on this release.
- Copilot and Codex as clients were not run (no account).
- The memory floor reads only `/proc/meminfo`; off Linux a hire is admitted unchecked.
- `HireToolTest#aHireStoppedFromThePanelEndsAtOnceAndSaysSo` failed in two of five runs while this work was in flux and passed in the last runs; its cause is not found.
- Windows and macOS are run by CI, not by hand.
- The known unfixed limits listed in the 4.6.10 notes stand.
