# jawata-mcp v4.6.13

**A hire runs on the brain and model stored for its seat, and when nothing is stored it is refused: a blank brain line is no longer Claude Code.** The Seats page, the chat's drop-down and Agent Control write and show one stored entry per seat; a hire reads that entry once, as a pair, when it starts. A change applies to the next hire of that seat only; a running hire is not touched. Needs jawata-studio 4.6.17 and jawata-chat 0.2.12.

## What changes

- **One stored choice per seat decides the hire.** A hire reads the stored brain and model together, once, when it starts. Nothing stored for the seat, an unreadable store, a brain no hire can start, or a brain the registry does not offer refuses the hire with a message naming the seat and where to set it (the Seats page, or the drop-down in the chat or Agent Control). No process starts. A seat file is no longer a source of brain or model: the `btw` and `rottenmeier` seat files no longer name one.
- **The choice is written safely.** The entry is replaced whole by writing a temporary file and renaming it over the old one; many threads saving different seats lose none, and a reader never sees one seat's brain with another's model. A broken file refuses the hire and does not stop the next save.
- **`brains` stores and lists the choice.** `brains(action=choices)` lists the stored entries (an empty list, not a default); `brains(action=set, seat, brain, model)` stores one seat's entry after checking the brain and the model against the registry, and tells every open chat. The engine opens the file at start; the resident reaches it through the exported engine package.
- **A command-line hire is started with the value the program takes.** A stored "Haiku 5.5" reaches Claude's command line as `--model haiku` (Claude refuses the display name); the hire's record keeps the display name.
- **A refused hire stays on the card as refused,** with the reason and no brain, instead of disappearing.
- **Only a seat's parent may hire it,** so the pm hires the two leads and not their workers.
- **A real Claude hire started through the command line can run tests.** Its tool server carries its plan id in the URL, as the chat's connection already did, and a hire attached to the resident is no longer started in plan mode. (Found by the dogfood after 4.6.12, where a hired Claude refused `run_tests`.)
- **Main's brain may search the web and fetch a page,** and a session can be asked for the newest model of a family (`latest:<family>`); the model menu is built at once and an agent that is not running has its models read in the background and sent when they arrive.
- **Test hardening:** a background hire finishes before its test closes the store it is still writing, which was the cause of `HireToolTest#aHireStoppedFromThePanelEndsAtOnceAndSaysSo` failing when run beside other hire tests (4.6.12 listed that failure with its cause not found).

## Known limits

- Shown on a throwaway engine with stand-in brains through two engine starts (11 of 11 and 3 of 3 checks: the refusal with nothing stored, the stored pair on the program's command line, the change reaching the next hire, the choice surviving a restart), and with the real Claude over the chat's own connection (Haiku stored, Claude answered as Haiku; changed to Sonnet, answered as Sonnet; 5 of 5). **Not yet shown:** a change made on the Seats page, in the chat and in Agent Control seen on the other two screens in a running studio, and a real Cursor, Copilot or Codex hire reading the stored choice.
- Six members are now called only by tests and are recorded in the hollow-wiring baseline with the reason: `HireRegistry#replace` and `AcpBrainSession#noteOffered` and the two `SeatHire` brain-pick forms belong to the pick-a-model-and-restart-the-running-hire path that the next-hire-only rule removed. They and their tests should be deleted; that is the next engine sprint's first cleanup.
- The memory floor reads only `/proc/meminfo`; off Linux a hire is admitted unchecked.
- Copilot and Codex were not run (no account).
