# jawata-mcp v4.6.3

**VS Code can refactor, test, debug and profile Java through the engine, with no other Java extension; and a hire answers at once and reports back later.**

This release replaces v4.6.2, whose tag exists but whose release run stopped in CI before publishing anything: a test class sat in two test jars. The changes are the same; the class moved.

## What changes

- **Refactorings are offered at the cursor** as editor code actions: inline a method or variable, change a method's visibility, pull a member up or push it down, make unchanged variables final, turn a constructor into a factory method, turn an anonymous class into a lambda, turn a singleton into an ordinary class. The editor applies each edit and can undo it. Two of them ask a question first (the new visibility, the factory's name).
- **The Testing view's requests are served.** `jawata/tests/list` names the test classes and methods with the scope that runs each; `jawata/tests/run` runs one, pushes `jawata/tests/progress` while it works, and answers with each failure's message and line. A run whose request the editor drops is cancelled, so no test JVM is left running.
- **A debugger answers on `/dap`.** The launcher takes `--dap` (as `--lsp` for the language server). It launches a program, arms breakpoints per file, tells the editor each stop, steps, lists the stack with the source file of each frame, opens variables, and evaluates an expression in a chosen frame. If the engine cannot follow the program, the editor is told why before the debugging ends.
- **`jawata/profile` records the person's running program and ranks its methods**, each with its source file and line.
- **A hire answers at once** with its plan id, its name and the state `running`; its result comes back to the principal's brain as a new turn. The `jawata.hire.background` setting is gone: this is how every hire works. Each hire has a first name that is unique in its conversation; a hire's parent is the lead that asked for it; stopping a lead stops everything under it; the number of background hires is capped; a hire may claim the packages it works in, and an overlap with another running agent is refused naming the holder before anything starts.
- **Found in live runs with Cursor's agent and repaired:** a hire asked for by the principal brain's own key is shown on that brain's chat; a session header sent several times is one identity; a bare success echo no longer ends the card of a hire that still runs; a refused hire's failed card no longer takes the events of the same call asked again; hire names come from one sequence per chat.

## Known limits

- The debugger needs `mainClass` and `classpath` in the launch configuration; the engine does not yet work the classpath out.
- Frames of anonymous classes and lambdas carry no source file, and breakpoints in nested or anonymous classes bind only to the file's top-level class.
- Moving a class is not offered as a refactoring.
- Checked on Linux in a real VS Code with only the jawata Java extension (one engine, no Red Hat Java server in the process list). Windows and macOS were not run.
