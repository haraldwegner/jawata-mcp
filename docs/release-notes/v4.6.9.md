# jawata-mcp v4.6.9

**A hired agent can work in the editor's folders, not only in Java projects, and a hire shows whether its checks passed.**

## What changes

- **A hired agent sees the whole workspace: the loaded projects and the folders the editor has open.** The studio hands the editor's folders to the engine (setting `jawata.workspace.folders`, environment `JAWATA_WORKSPACE_FOLDERS`). Before, a hire whose working folder was a non-Java folder of your editor workspace was refused (`ACCESS_DENIED`, "outside every place the access policy allows"). Shown in a sandbox: without the setting the hire is refused; with it, a hired developer changes a text file in such a folder (`28h-S22-evidence/s27-p-probe`).
- **A step can say what it must find.** A search step states how many matches it must find, zero included, and a search that found nothing no longer passes. A step can also state that the tree must have changed (`expect.changed`), read only from a `git_diff` lookup. A hirer's stated count now survives when a seat adds its own check ahead of the hirer's steps (this was lost before).
- **A hire's record says where its time went.** The record carries `toolMillis`, the time a tool call of its brain was open, beside `elapsedMs`. In three small hires 8 % of the time went to tools.
- **A hire the engine refuses leaves no card.** The chat takes back the card it drew from the call; before, a refused hire stayed listed as failed.
- **Agent Control counts a run's calls.** Each hire's answer says how its calls split (jawata, other, shell on Java), lists the shell calls on Java with the reason they declared, the jawata calls that failed or were refused, and how many of its steps ended with no passed gate.
- **Hiring.** A lead may hire its sub-lead's workers, so the project manager can send an easy task straight to a developer. A lead keeps waiting for a hire of its own that is still running. A worker that finishes with an unchanged tree although its brief held an instruction is reported as such.
- **`files` can replace one passage of a `.md` file** (`edit`), so a plan can be amended without rewriting it.

## Known limits

- The editor-folder change was shown on Linux with Claude only, one hire per run. Windows and macOS are run by CI, not by hand.
- A diff shows only the unstaged changes of tracked files, so `expect.changed` reads a new file or a staged change as no change.
- Two items of Agent Control are not built: calls that cannot be tied to a run shown as unassigned, and a client the hook does not watch shown as not observed (named to the owner as ledger row 28h-C27-11).
- The known unfixed limits listed in the 4.6.7 notes stand.
