# jawata-mcp v4.3.2

**Loading, importing and rebuilding the memory store no longer make the caller wait.**

## What went wrong

When the store takes in many notes at once — a story folder being loaded, an import, a rebuild —
each note also gets a meaning vector, which is what lets a question asked in different words find
it. Until now the store worked out every one of those vectors before it answered, at about a second
a note. After a loader change, when every story is read again, that made a load take five to six
minutes, and whoever asked — studio's reload, or an agent — sat blocked for all of it.

## What changes

- **The store answers at once.** The answer says how many notes are still waiting for their
  meaning vector (`unembedded`) and that the vectors are being computed in the background
  (`embedding: background`).
- **The vectors are computed behind the answer**, by one background worker. It picks up notes
  written while it is already busy, so none are left waiting for the next restart.
- **Only one vector pass runs per store at a time.** When a load arrives while the engine is still
  catching up after a start, the two no longer compute the same vectors twice.
- **While a note is waiting, nothing hides it.** A question that meets such a note marks it rather
  than scoring it zero, and `experience(kind=stats)` reports how many are left until the count
  reaches zero.

Works with jawata-studio 4.3.3, which also reloads the store whenever an engine starts.
