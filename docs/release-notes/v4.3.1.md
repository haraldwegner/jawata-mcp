# jawata-mcp v4.3.1

**Two fixes to what the memory store hands an agent.** Both were found by using 4.3.0 on a real
store.

## A section heading is no longer stored as knowledge

The store loads story files. Until now every `## ` heading in a story became a row of its own,
with the heading as its whole summary — "The case", "The cure", "Boundary". On the store this
was found on, that was 49 of 384 rows, and recall and the prompt hook handed them to agents as if
they were knowledge. A story's headings are the steps of its one argument; out of the story they
say nothing.

**What changes:** a story file is one row, and its headings stay inside its text. The heading
rows already in a store disappear the next time the story folder loads — studio runs that load
after every deploy — because this version reads each story file once more and removes the rows
the old split left behind. Nothing a story says is lost: the text those rows held is on the
story's own row.

## A question asked in different words can find the right note

When an agent asks the store a question in its own words, each note gets two scores added
together: how close its meaning is, and how much of the question's wording it shares. The wording
score was scaled so the best match always counted as a perfect match — even when it shared one
word. So a note sharing one word of a paraphrase could outrank the note that answered it. On the
store this was found on, "at what point may I treat pulling back an instruction I gave the
exchange as finished" put a lesson about standing instructions first, on the one word
"instruction", and the note that answers it was not in the top eight.

**What changes:** the wording score now measures how much of the question's distinctive words a
note carries. A note sharing one rare word of a twelve-word question gets a small share of the
wording score, not all of it, so it can no longer outweigh a note whose meaning fits. Common words
still count for almost nothing, as before.
