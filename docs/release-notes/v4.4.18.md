# jawata-mcp v4.4.18

**`run_tests` no longer tests the first loaded project whatever holds the class, and its output tail keeps the line that explains a failure when a library prints hundreds of DEBUG lines after it.**

These came from running 4.4.17 on the design-patterns workspace (194 projects loaded) and on this project's own workspaces.

## What went wrong

- **`run_tests` with a class or package scope ran the first loaded project.** With several projects loaded, a test class that lives in the third project was looked up in the first, found nothing, and the run answered success with zero tests. `coverage_import` and `coverage_mutation` took the first project the same way.
- **The output tail dropped the cause of a failure.** The tail is the last 100 lines of the run. DEBUG and TRACE lines were removed after those 100 lines had been cut, so a run that printed one INFO line (the reason for the failure) and then more than 100 DEBUG lines showed 100 lines of noise, and the INFO line was gone. The comment next to the code also claimed the tail was cut at 80 lines, which it never was.

## What changes

- **With one project loaded nothing changes. With several, a type or package scope without `projectKey` is refused** (`INVALID_PARAMETER`, parameter `projectKey`). The refusal lists the loaded project keys in alphabetical order (up to 20), says what settles it (`projectKey`, or an absolute file path inside the project) and points to `project(action=list)`.
- **A file scope uses the project that holds the file.** The path must be absolute; a relative path, or a file inside no loaded project, is refused with its own sentence.
- **`coverage_import` and `coverage_mutation` refuse an unnamed project in the same way.**
- **The answer of `run_tests` (both `run` and `start`) now carries `project`**, the key of the project it ran.
- **The tail filter runs before the last 100 lines are taken.** The header still says how many DEBUG/TRACE lines were left out.

Each change has a test that fails without it: `RunTestsNamesItsProjectTest` (five cases) and `RunTestsOutputTailTest#theInfoLineSurvivesMoreDebugLinesThanTheTailHolds`.

## Behaviour changes

- **A `run_tests` call that named a type or package and no `projectKey` is refused when more than one project is loaded.** It used to run the first project. Callers in a many-project workspace must pass `projectKey` (or an absolute `filePath`).

## Known limits

- **The output tail is the last 100 lines of the first 1,000,000 characters the runner printed.** The runner's output is captured up to that size and the rest is dropped, and DEBUG bytes count against it before the filter runs. A run that prints more than about 10,000 DEBUG lines before its failure shows a tail without the failure. Planned: a bounded ring of the last non-DEBUG lines.
- **The refusal lists project keys, not owners.** With 194 projects loaded the owner is rarely among the 20 keys shown. Planned: the workspace answers which projects hold the type.
- **A run that discovers zero tests still answers success, with a note.**
