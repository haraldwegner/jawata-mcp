# jawata-mcp v4.4.14

**A Maven project that fails to resolve no longer keeps a stray classpath file, and the engine's own tests stop writing into its sample projects.**

## What went wrong

- **A Maven import that timed out or failed left a `jawata-classpath-<pid>-<id>.txt` file in the project's `target/` folder for good.** The file was deleted only after a successful read, so a failure kept it. This happened in users' own projects as well as in the test samples.
- **The engine's tests imported the sample projects in place,** so Gradle, the compiler and Maven wrote `.gradle/`, `bin/` and `target/` into the repository's test resources.

## What changes

- **The classpath file is deleted on every path.** After a failed or timed-out run, the engine looks for its own file under the project and removes it. If it cannot, it logs a warning and the import result is unchanged.
- **Every test gets its own copy of each sample project.** Inside a test, the helpers hand out the copy and refuse when there is none, so a test cannot quietly use the original.
- **The suite fails when the sample projects differ from git in any way:** untracked, ignored, changed or deleted files. The new gate is `build/test-resources-clean-gate.sh`. Before the fix, one test class left 16 paths behind; it now leaves none.

Works with jawata-studio 4.4.9.
