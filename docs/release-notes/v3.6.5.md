# jawata v3.6.5

**Three answers that did not match the question they were asked.**

## "Just give me the counts" now works everywhere

A scan of a large project can return thousands of problems — too many to read, and
past the size limit of most agent clients. `summary=true` exists so you can ask
for counts instead of the full list.

It worked for one family of checks and was silently ignored for the rest. Ask
`unused`, `naming`, `large_classes`, `bugs` or `circular_deps` for a summary and
you received the entire list anyway, with nothing in the reply saying the request
had been dropped. v3.6.4 fixed exactly one of the six cases; this release fixes
all six.

Paging (`limit` / `offset`) had the same hole and now follows the same rule. The
summary also names which list it summarised and always carries the total, so a
count is never left implicit.

## The architect watch was reading a third of what it was given

The watch that says *"here is what your change just broke"* understood two of the
six answer shapes a check can return. For naming, bugs, large classes and circular
dependencies it saw nothing — which is indistinguishable from a clean change. It
now reads all six.

## A reference you cannot open now says so

Asking who uses a type could return a directory instead of a file, with no line
number and no error. It read like an ordinary result that simply would not open.

Such a row now either carries a real file and line, or states plainly that it
could not be resolved and why. A lookup that failed is no longer reported as an
answer.

## Verification

The full suite passes: 1715 tests, 0 failures (2 skipped — they need a private
corpus that is not on the build machine).

The new tests were also run against the *unfixed* code, where 10 of the 11 fail.
A test that passes before and after a fix proves nothing; these detect the defect
they describe. The eleventh guards the reference-row rule but needs a specific
broken-workspace setup to trigger, so it is not claimed as proof.
