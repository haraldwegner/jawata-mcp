# jawata-mcp v3.12.0 — the workspace resolve phase

**A PDE/RCP workspace now resolves as a whole.** On the reference workspace — 29
projects, a real Eclipse RCP product plus its Maven-built gateways — jawata reported
**1229 compile errors** against code whose own build was green. It reports **0** now.

## What changed

Projects used to resolve their dependencies *during their own import*, against
whatever happened to be registered so far — so a plug-in that loaded before its
provider never saw it, and the error said `import … cannot be resolved` about a
type that was demonstrably present. Resolution is now a **workspace phase**:

- **Inventory** — every bundle's manifest is read once into facts (Require-Bundle
  with version floors, `visibility:=reexport` and `resolution:=optional` kept as
  data, Import-Package, Export-Package, Fragment-Host, Bundle-ClassPath,
  Eclipse-PlatformFilter).
- **Resolve** — one pure pass over the complete graph decides every bundle's
  wiring: workspace projects win over jars, newest version satisfying the declared
  floor, cycles are legal, re-export closure walked transitively, fragments filtered
  to the running machine's os/ws/arch and attached beside their host.
- **Apply** — a delta apply touches only the entries jawata owns (marked
  `jawata.wire`); source folders, containers and hand-authored `.classpath` entries
  are preserved verbatim. Loading, adding or removing a project re-resolves the
  workspace inside one workspace operation.

## The target platform, without an Eclipse installation

The external bundle pool now indexes the **Tycho p2 cache**
(`~/.m2/repository/p2/osgi/bundle`) in its nested `name/version/jar` layout — what
the user's own build already downloaded. 673 jars index in 243 ms, 16 ms once
cached, with per-jar fingerprints so a new version or an in-place replacement is
picked up without a restart. `refresh_workspace` clears the caches, recomputes the
wiring, and says so (`wiringRecomputed`).

## Also in this release

- **`Bundle-ClassPath`** — a bundle's own nested jars reach its classpath and its
  dependents (exported), deduped against `.classpath` entries naming the same jar;
  a jar declared but missing, or nested inside a packaged pool jar, is reported
  rather than silently dropped.
- **Unresolved-dependency reporting** — `inspect(kind=classpath)` and
  `health_check` carry what the import asked for and could not find, with a reason
  per row. Always present, empty when everything resolved.
- **Declared shapes that lied** — `run_tests` now declares every action its
  dispatcher accepts (18, not 4, `impacted_tests` among them);
  `find_references` reports the true total rather than the page cap in both fields;
  sweep findings name their project; a family sweep without `action` refuses in
  milliseconds naming the async path.

## Closed

- **#3** — synthesized workspace loses the classpath (JRE, PDE requiredPlugins,
  JUnit containers, project references).
- **#11** — Require-Bundle resolved one level deep, so re-exported bundles never
  reached the build path.

## Upgrading

No configuration change. A workspace whose projects previously resolved nothing
will resolve them on the next load; existing `.classpath` content is preserved.
