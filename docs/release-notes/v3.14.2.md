# jawata v3.14.2

One deliverable and its guard, both demanded by the sprint's close-out audit.

## Added — `origin_client`: which client recorded each entry

Every entry the `record` verb writes is now stamped with the client that wrote
it — `claude_code`, `cursor`, `codex`, … from the closed vocabulary, never a raw
client string. The stamp is applied by the event tap (the one place that holds
both the completed call and its session), so no tool signature changed. An
import keeps the ORIGINAL attribution: origin is who wrote an entry, not who
moved it. NULL and `unknown` stay distinct facts — "nothing ever stamped this
row" versus "the stamper ran and the session was not identified".

Delivered on the condition its own deferral note set at v12: the column arrives
together with every site that spells the row shape (export, import, orphan
recovery — version-gated), its writer, and its reader (`stats.by_origin_client`).

## The guard that proves the process

v12 shipped a test asserting the column ABSENT, with the delivery condition in
its failure message. The delivering commit's first suite run went red on exactly
that guard — the mechanism working twice: it blocked the column arriving early
without its writer, and it forced the delivery to flip the assertion
consciously. The guard now asserts the column present.

## Gates

Suite green with the flip · end-to-end green including the new
`origin-attribution` promise (a front-door record is countable by its recording
client) · wiring gate PASS · attribution audit clean.
