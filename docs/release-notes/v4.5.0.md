# jawata-mcp v4.5.0

**The engine can now be the agent your editor talks to: it answers the Agent Client Protocol, hires other agents for the steps of your work, shows each hire as a card you can stop, accept or reject, and checks every tool call against a policy of places you allow.**

Until now jawata was a set of tools that an agent in your editor could call. In 4.5.0 jawata also stands one level above: you talk to jawata, and jawata hires the agent that does the work. The tools are the same; the engine is what changed.

## What you can do now that you could not before

- **Talk to the engine as an agent.** `java -jar jawata.jar --acp` is a stdio program any ACP client can start (the studio's chat, Zed, IntelliJ). A prompt is answered by the main seat running in a vendor agent that you name in the setting `jawata.agent.brain`; its answer streams back as it is written, and the next prompt continues the same brain session.
- **See and steer each hire.** A hire reaches the client as a card: seat, task, brain, model, state, time, tokens, and cost when the brain reports one. You can stop one running hire, pick another brain for a seat (`seat-model:<seat>`), unfold what the hire was told and answered, and list or reload old sessions from the transcript lane. A hire's proposal arrives as a request with the changed files as diffs; your accept or reject is stored with the hire.
- **Let it run, and take it back.** An autonomy switch (off or on) lets the engine resume a step that is not finished; only your own message ends the grant, a message from a hired agent never does. Three tries per step, then the refusal names the free check that settles it. Your cancel stops the prompt and the resumption.
- **Keep hired agents inside a tree.** Seats may be hired only by their parent (the pm hires the chief engineer, not the cataloguer). A seat's tool list is enforced at the engine, whatever the brain does about permission, and a code-changing tool is refused to a lead. A consultant is never on the main seat's vendor. A developer whose gates fail is answered by the senior developer.
- **Decide where a tool may touch.** One policy file (allowed places, denied places, deny wins) is read on every call, for every client. A place on neither list is refused; a missing or unreadable file refuses every place and says which. The default is written once to the data folder and never overwritten.
- **Two new tools, 46 in all.** `plan_steps` shows which steps of the current plan are pending; `plan_board` draws a plan file's board from the engine's own ledger between its markers, so the board and the ledger cannot differ.
- **Review before send.** With `jawata.agent.reviewer` set, the main seat's text is held and only the reviewed text reaches you; a review that does not answer sends a sentence saying the message was held, never the draft. An observer checks that a worker ran the instruction as written.
- **Seats as prompts.** The engine serves the seat files as MCP prompts. A seat that changes code gets the area's jobs from the code lane burned into its prompt; a rule labelled `tool:<name>` rides that tool's answer.
- **Seats on a schedule.** A seat file may declare its own schedule and gate; the scheduler hires it through the same hire path.
- **A language server on the same listener.** Hover, definition, references, rename, formatting, code actions, folding, semantic tokens, inlay hints and live problems for unsaved text, answered by the engine's own compiler.
- **After a build-file change, the next answer says so** (pom.xml, build.gradle, .classpath, MANIFEST.MF) and names `refresh_workspace` as the step; nothing is re-imported unasked.

## Behaviour changes

- Every hired session is bounded by its seat's tool list. A dialect seat that lists no tools stays unbounded (a declared residual).
- A tool call naming a place the access policy does not allow is refused, for every client. Check the shipped default before relying on a place outside your workspace.
- This release carries 4.4.18 to 4.4.20 (`run_tests` runs the project that holds the type, its output tail keeps the end of the run, a stopped engine's recall warm-up no longer switches the embedder on).

## Known limits

- **Only one vendor's agent has carried a real turn** (Cursor's agent, on Linux, through the chat). Copilot's agent refused at its own context budget; no second vendor has been tried.
- **Revert of an accepted hire is not built.** Accept and reject exist; undoing an accepted change is a manual step.
- **Not run on Windows, macOS, Zed or IntelliJ.** Those rows are open; the language server has only been driven from a VS Code window.
- **Cursor reports no token counts**, so those read 0; a hired seat nobody types has no typed command in the chat's list.
- **Two hires of the same seat with the same brief at once share one record.**
