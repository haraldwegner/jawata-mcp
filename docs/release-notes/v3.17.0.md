# v3.17.0 — a reseed only deletes what it can rebuild

One behaviour change, found by dogfooding v3.16.0 the day it shipped: the stop gate
made `experience(kind=reseed)` the routine repair, and the reseed was destroying
knowledge it could not restore.

## The rule

The store holds rows of several origins, and only one of them has a file behind it.
The old reseed deleted every row and reloaded from files, which silently destroyed
the rest. The new reseed owns exactly the file-derived lane:

| Origin | Old reseed | New reseed |
|---|---|---|
| stories loaded from files | deleted; in-scope reloaded, excluded refs tombstoned | **unchanged** |
| the pattern catalogue (bundled snapshot) | deleted; returned only at the next resident start | **kept**, reported under `kept.catalogue` |
| direct records (`kind=record`, no file) | deleted — permanently, nothing could restore them | **kept**, reported under `kept.recorded` |

The store has carried a `provenance_kind` column since schema v10 and no verb ever
read it to decide anything. This is that missing concept, expressed where it is
decidable: a wipe may only delete what something can put back.

## What deliberately did NOT change

**The curation instrument.** Within its lane the reseed stays total: excluding a
source by reseeding a narrower root still removes it and tombstones it, so the
deploy-time crawl cannot re-import what a reseed deliberately kept out. A first cut
of this fix scoped the delete to the reseed's path — safer-looking, and wrong: four
tombstone tests went red because kept-out pollution would have been kept in.

**Revival.** A tombstoned source is still revived by reseeding a root that contains
its file. That half of the contract used to ride the full wipe; it now has its own
verb, `clearTombstones()`, arriving together with its caller.

**The bare `wipe`.** It still removes everything. "Remove everything" is a verb the
store keeps; it is no longer a side effect of the routine repair.

## The response says what survived

A reseed reports `kept: {catalogue, recorded}` beside `removed`, `loaded` and
`tombstoned` — because "the reseed spared them" and "there were none" must not read
identically.

## Also in this release

- CI/release workflows move to `softprops/action-gh-release@v3` and
  `gradle/actions/setup-gradle@v5` — the Node 20 runtime both were pinned to is
  deprecated on GitHub runners. `setup-gradle@v6` was considered and rejected: its
  caching component is no longer open-source.
- A javadoc false positive: prose beginning `@deprecated` at a line start is parsed
  by javac as a real block tag; now written `{@code @deprecated}`.

## Compatibility

No schema change — v15 stores are unaffected, no migration runs. The `reseed`
response gains the `kept` block; `removed` now counts only file-lane rows.
