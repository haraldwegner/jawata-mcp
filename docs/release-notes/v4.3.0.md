# jawata-mcp v4.3.0

The knowledge store stops being a cache that happens to persist and becomes a database. The
thread running through every change below is one distinction: **an absence has to be SPOKEN.**
A store that answers "nothing" when it means "I could not look" is worse than one that answers
nothing at all, because the first is believed.

## A committed write survives everything

A maintenance run used to be able to lose a story. The load is an upsert now — it merges in
place and removes nothing — so a load that dies halfway leaves the rows it already wrote. The
property is **no loss, not no change**, and it is written into the test's own javadoc rather
than implied: nothing is retired until a load has returned and delivered.

The two runs of 2026-09-08 that cost the rows are kept as regression cases and replayed. The
14:04 run — a load that did not complete — now leaves the store unchanged.

## Every destructive verb leaves a copy, and hands you the path

`wipe_and_import`, `wipe`, `prune` and `import` each write a copy beside the store before they
touch it and return that copy's path in their own response — measured through the front door
against this build: `prune` handed back the archive it had just written. Older copies are rotated
rather than kept forever, so the directory does not grow without bound.

This exists because `prune` has no delete-by-id and once removed 101 entries when seven were
asked for. The undo is now a file you can name.

## A story is searchable by meaning the moment it is written

Record a story and a cue that shares none of its words reaches it — measured through the front
door against this build, not in a unit test: a row written seconds earlier came back for prose
with no keyword in common. `stats` reports how many rows lack a vector, and the backfill drives
that to zero and says so.

## Imported markdown is no longer stamped `java` (mcp#57)

`language` is not descriptive metadata — it gates JDT staleness, so an entry about a broker's
order book stamped `java` was eligible to be staled by a compiler that could never resolve it.
Markdown that declares no language is now counted outside `java` and the staleness sweep leaves
it alone.

## Four lanes, four lifecycles — and a file edit alone triggers nothing

Experience, domain, code and rules are separate lifecycles, retrieved separately. The
shown-often-chosen-never sweep reports **per lane and per trigger**; the aggregate number that
told you nothing is gone.

The half worth stating is the negative one. A bare `Edit` used to fire the symptom lane on words
taken from the file's own path — asking the store about "importer" on every edit of every file.
It triggers nothing now, and the hook says which rule stopped it rather than reporting the store
as empty.

## The code lane: what this package is for, and where that job lives

Two new row shapes. An **area** says what a package is for; a **job** says what one member does,
anchored to that member. Ask what a package does and you get its summary; ask for a job and you
get its file and line **resolved at that moment** — rename the method through jawata and the
answer follows; rename it outside jawata and the job reads "location lost", queues, and answers
again after re-anchoring.

## The duplicate gate: told before you write it, not after

An agent about to write a method that already exists somewhere under another name is told so at
the only moment the telling is free. A `.java` write carrying a draft is read, its methods are
asked of the code lane BY MEANING, and the nearest recorded job comes back with its address.

**It SHOWS and does not DENY, and that is a declared deviation from the plan's ruling.** The
reason is a measurement rather than a preference: the ranking applies no score threshold,
because three of ten genuine task-to-job pairs score at or below the noise floor, so rank one
always comes back. A gate denying on that would deny every Java write in the repository and be
switched off within a day — taking the honest half with it. `Block` ships, configured
explicitly, and is not the default.

A second deviation sits under it: the draft is parsed standalone rather than as a JDT working
copy, so the structural confirmation that would justify blocking has no bindings to run on. That
is work not done, not a wall, and the mode does not rest on it.

**READ THE THREE LIMITS TOGETHER, because each is separately reasonable and they stack.** This
gate advises rather than refuses; it has no confirming structural signal, because the draft is
parsed without the compiler; and it subtracts what a file already declares BY METHOD NAME ALONE,
so a draft adding `parse(ICompilationUnit)` beside an existing `parse(String)` is skipped as
already present — a new overload next to an existing name being one of the commonest shapes a
re-derived job actually takes. Taken together this ships narrower than "the duplicate gate" reads:
it is a good nomination, shown early, that is quietest at its own likeliest case. The arity fix
needs a project-loaded fixture and is the next sprint's.

## The re-derived job: the duplicate a token comparison cannot see

A new `find_quality_issue(kind=re_derived_job)` names methods that answer the same question from
the same collaborators and were written independently — grouped, with each group's shared
signature shape. It is the opposite question from `duplicated_code`: that one finds the duplicate
whose TOKENS match, this one finds the duplicate whose tokens cannot.

Run over jawata's own tree: 475 files, 4088 methods, and the parse-helper population named at
**34 members in one group** — the population a previous sprint recorded by hand and left
unmerged. The token finder at its most sensitive groups 28 of them; the two sets agree on 27, so
**7 are named by this detector alone**. That gap is the whole claim.

## Recall answers the caller's limit

`experience(kind=recall)` capped its answer at five rows and ignored `limit` entirely. Five rows
is right for the hook, which injects into a prompt on a budget, and wrong for a caller asking a
POPULATION question — the architect seat asks one precisely to notice a job written twice, and on
a package of fourteen jobs the five returned carried a re-derived job **without the job it
re-derives**. A detector shown half a pair cannot find a pair.

The cap did not go away, it became the caller's. A caller naming no limit still gets five, and
`capped_from` still travels whenever a cap bites — a sample that does not say it is a sample is
the absence-not-spoken this release is about.

## The catalogue manifest drops three fields nothing read (mcp#67)

`type`, `category` and `tags` leave the extraction. Verified before removing rather than assumed:
no reader for any of them in the seeder, the manifest or the sources. The artifact is regenerated
against the fork at its documented pin — 187 rows before and after, every surviving field
unchanged.

What is kept is the PARSE. The readers still handle both spellings, because the measurement
behind them cost real work and is still true: 185 of 187 upstream READMEs write `category:` and
182 write `tag:`. The finding is kept; its unread output is not.
