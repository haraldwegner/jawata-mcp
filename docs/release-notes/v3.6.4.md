# jawata v3.6.4

**Three ways a tool answered something other than what it was asked.** All three
were found by working v3.6.3 in anger the day it shipped.

## jawata rejected its own output

The worst of the three, and it had been there a long time.

Ask about a file by its full path and the answer comes back correctly — and
reports the file's path in the short form, relative to the project. Take that
short form, hand it straight back, and jawata says **the file was not found**.
The file exists. The path came from jawata.

That is the most natural thing an assistant can do: use the path from the last
answer in the next question. Doing it produced a confident, wrong "does not
exist" — the same shape of untruth as a failed lookup returned as an empty
result, because nothing in the reply distinguishes it from a real absence.

The reading side accepted only full paths and abandoned anything else; the
writing side had been returning the short form all along. They sat four lines
apart in the same file.

Now the reading side accepts the short form as well, wherever a file is
resolved — not only in the one tool this was noticed in, but in all thirty-five
that resolve a file, because the fix lands at the single point v3.6.2 unified.
**Nothing about the output changed.** Only what jawata is willing to accept.

Why it stayed hidden: on a project laid out the Maven way the short form
already worked, through an older fallback. It failed only for projects whose
source folders are named something else — the same projects as the last two
releases' defects.

## "Give me counts, not the list" was accepted and ignored

Asking for a summary of one analysis returned the entire findings list, with
nothing to say the request had been dropped. The option was documented as
applying to a whole family of analyses only, so asking for it on a single one
was outside its contract — but silently discarding what the caller asked for is
still the wrong answer to the question.

It works for both now. The default output of a single analysis is unchanged: it
still returns everything unless you ask for paging.

## The summary that could not be read

The summary shape exists so a sweep of a large project can be read at all. It
correctly left out the findings — and then returned the full list of conflicts:
295 entries, about 111,000 characters, past what an assistant can receive. The
one shape built to be readable was the shape that could not be read.

The conflicts list is now capped like everything else, the true total is
reported beside it, and a capped list says that it is capped.

## Verification

Full suite 1702 of 1704 passed, 0 failed (2 are skipped without a private
corpus and say so). End-to-end suite against the built artifact: 36 of 36.

Nine new tests. **Seven fail on the unfixed build**, each on the symptom it
describes — including the one that reproduces the field failure exactly: a path
this release's own formatter produces, refused by its own resolver.

Nothing about recall, the experience store, or the tool set changed; the tool
count stays 45.
