# jawata-mcp v4.4.2

**A hired Claude no longer has its own built-in tools, so a seat's tool list now limits what it can do.**

## What went wrong

- **A hired seat could use tools its file never listed.** 4.4.1 gave a hired Claude only the jawata engine that hired it, but its own built-in tools stayed available. A PM seat whose file lists read operations only, told to edit a file, used Bash three times, started a sub-agent, and wrote a plan file outside its working folder. It never called a jawata tool.
- **The hire record's containment line was out of date and its own caveat contradicted the evidence.** It said a Claude hire is "NOT write-contained by a mechanism".

## What changes

- **A hired Claude starts with no built-in tools** (`--tools ""`), so the seat's jawata tools are the only ones it has. In 6 hires of the same PM seat told to edit a file, no file was written anywhere and no plan file appeared. In 5 of the 6 the brain still tried a built-in tool by name, such as Write, and said it was unavailable.
- **The hire record says what was measured, and no more.** It names the flag and states "measured, not proven: 6 of 6 hires wrote no file". It also explains that an attempted call is counted as a call, because the engine reads which tool the brain asked for, not whether the call ran.

## Known limits

- **The record cannot tell an attempted tool call from an executed one.** A refused Write still reads as a code-changing call, so the "no code changed" measure for a Claude hire is not a clean zero. Reading each call's result is the cure and is not in this release.
- **Six hires are an observation, not a guarantee.**
- **Only an HTTP engine gives a Claude hire this start.** A stdio engine keeps the user's own setup. Cursor, Copilot and Codex hires are unchanged.

Works with jawata-studio 4.4.1. No studio release is needed: studio installs the latest engine.
