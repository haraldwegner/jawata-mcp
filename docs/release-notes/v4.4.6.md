# jawata-mcp v4.4.6

**A resident whose listener has died exits instead of staying deaf, and a hired brain's bounds are stated from what was measured.**

## What went wrong

- **A resident could be alive and deaf.** On 2026-10-15 the javata-dev resident, up ten hours, answered no request: its HTTP listener thread had died while the process lived on, with 51 connections queued against a backlog of 50. Nothing restarted it and the studio could not tell it from a slow one.
- **The hook's recall ran past its 200 ms deadline on a large store.** Each entry the fit gate checked wrote two counters synchronously, about 22,000 writes for one recall over an 11,000-entry store.
- **A hired claude was offered the engine's code-changing tools its seat never named.** `--allowedTools` only pre-approves; the rest stayed offered, so a read-only seat could still reach `rename_symbol`.
- **A brain whose writes are held only by an instruction could be hired without anyone saying so.** Cursor was breached in 5 of 15 runs under its instruction.
- **A proposal's first line said "NOTHING HERE WAS APPLIED" whatever the run did,** and a hired run's argv could be set by a caller and thrown away unread.
- **The shipped-tool list had no single source.** A probe said 43 tools, the studio help 45 and the registry manifest 63, against 44 shipped, and three tool names in the registry's read-only and no-steering sets named tools that no longer exist.

## What changes

- **A dead listener is noticed.** The transport asks its own `/mcp` every 30 s; three silences in a row declare it deaf once, log an error, and exit with status 70 (halting after 15 s if the graceful exit hangs), so a supervisor sees a dead resident.
- **A recall writes each fit-gate counter once,** not once per entry it checks. Measured on a synthetic store of 11,209 entries: 120 of 120 recalls inside the 200 ms budget (slowest 132 ms).
- **A hired claude is not offered the engine's code-changing tools the seat did not name,** by the engine's own flag. Every brain now says what stops it writing, mechanism or instruction, and a brain held only by an instruction is refused before anything starts unless the seat says `accepts_uncontained_writes: true`.
- **A proposal says what it applied by reading the changed-file census, and what that census covers:** the working directory only. The manifest gains `appliedScope`; `applied` and `changedFiles` keep their meaning.
- **A hire's answer carries its journal row and a reason for every gate that did not answer.** `HiredRun`, `HiredBrain` and the hire tool take a `HireSite` (where the brain runs, with what environment) and no longer a command whose argv they discard.
- **`ShippedTools.build` is the one producer of the shipped tool set** and registers nothing, so which tools ship can be asked. The registry's stale names are removed. The end-to-end test and the C5 probe read the expected count from the README's tool inventory instead of a literal, and `server.json` states no count.
- **Smaller:** a file's compile problems are read when no editor has it open, and `organize_imports` reads its tree through that shared parse; a cleanup that removes a member takes its separator; a declined or unresolved import is named; a first look at a file is not labelled "new since your change"; a nested type named as the source names it finds its class file; a missing embedder is a skip, never a pass; a hired seat its owner switched off is refused; a seat can name the script escape hatch and its executable.

## Known limits

- **The watchdog is proven by tests against a real listener stopped behind a living transport, not by a released resident.** Running 4.4.5 residents do not have it; confirm after this release that a resident whose listener is stopped exits within about 90 s. Why the dispatcher thread died is not established.
- **The recall measure is on a synthetic store,** not a real one, and the slowest symbol-cue call used about half the budget.
- **The off-tree bound is the working directory.** The hire's census cannot see a write anywhere else; codex, copilot and cursor off-tree behaviour is unmeasured. The containment probe lists claude's plans directory before and after each claude cell, and the first live run of the claude cells saw no off-tree write at all (the plan-mode runs declined in words and wrote no plan file), so the listing is proved by a stand-in claude only. It sees what changed in the directory, not which process changed it, and a rewrite that leaves size and modification time unchanged goes unseen.
- **A brain that declines in words is scored contained by the probe.** Only the cell with the editors removed is a mechanism; in its three live runs the brain tried to write and nothing was written.
- **Deleting the gate runner's unreachable catch is closed on mutants and a green run,** not on a test that failed before. The registry is total over Exceptions and no wider: an Error before dispatch still escapes.
- **The registry manifest** (`server.json`) needs a re-publish before the MCP registry shows its new description.

Works with jawata-studio 4.4.2, which words status 70 and a resident that accepts no connections.
