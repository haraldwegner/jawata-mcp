# jawata-mcp v4.4.15

**A Maven parent project no longer reports its modules' classes twice, a Gradle project opened through a link mounts each source folder once, and a store shutdown during background indexing leaves no error file behind.**

## What went wrong

- **A Maven parent project with its own `src` folder loaded with false errors.** In java-design-patterns, `page-object` groups two modules and also holds a stray `src/main/java` and `src/test/java`, which Maven never compiles for a `pom`-packaged project. The engine mounted them beside the modules' folders, so four classes were "already defined", and `run_tests` refused a project Maven builds cleanly.
- **A Gradle project opened through a link got every source folder twice.** Gradle reports source folders by their resolved path, and the engine kept the path the project was opened with, so a project under a link (the macOS temp folder is `/var` → `/private/var`; Windows paths may carry a short name such as `RUNNER~1`) mounted four roots instead of two. In 4.4.14 this made CI fail on macOS and Windows.
- **Closing the knowledge store while background indexing ran left `experience.trace.db` in the store folder.** The indexing job used the store's connection without holding the store's lock, so a close could shut the connection under a running query.

## What changes

- **A `pom`-packaged project's own source folders are not mounted; its modules' are.** The decision reads the packaging the build file declares, so a jar project that names modules only inside a profile keeps its own sources. A `pom` folder with sources and no modules still loads them through the engine's discovery by package declaration.
- **Source folders Gradle reports inside the project are put back in the project's own spelling** before duplicates are removed.
- **The background indexing job's queries take the store's lock**, as closing the store does, and compute their vectors before taking it, so writers are not held up. The recall searches are left as they were and may still fail if they race a shutdown; that is recorded beside the store's connection rules.
- **The engine's tests run on resolved temp folders**, as they ran on the repository's own paths before 4.4.14.

Each change has a test that fails without it.

## Known limits

- **On Windows, a path given in short-name form (for example `C:\Users\RUNNER~1\...`) is not matched to the project loaded under its long name.** The tests no longer exercise it; the fix is planned for the OS-coverage sprint.
- **When the machine's limit on file watchers is reached, the workspace watcher does not start, and neither does its fallback poll**, so changes to `workspace.json` are not picked up until a restart. A fix is planned for Sprint 28h. On Linux, raising `fs.inotify.max_user_instances` avoids it.

Works with jawata-studio 4.4.9.
