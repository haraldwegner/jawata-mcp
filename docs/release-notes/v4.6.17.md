# jawata-mcp v4.6.17

**Hired agents run their commands through jawata, hires no longer have limits of time, cost or number, and the pm works from a plan the engine holds.** Needs jawata-studio 4.6.21 and jawata-chat 0.2.17.

## Commands go through jawata

- A new tool, `shell`, runs a hired agent's command line. A hired Claude agent's own command line is switched off; it keeps its editors. Main and the leads have no shell.
- The shell refuses: writing a Java file (unless the command gives `jawata-author:`), a text search over Java (unless it gives `jawata-fallback:`), `git commit` and `git push`, and a command that runs more than a single test (the tester runs those). A run of many tests is also refused when the machine is short of memory.
- It is not a sandbox: it judges the command as written, so a script can get around these refusals, and `gh release create` is not blocked.

## Hiring

- No limit on the number of running hires, and none of time, cost or tool calls per hire. A hire that reaches its role's context size is told to report, and is replaced.
- `hire_wait` waits up to 10 minutes, answers what a running hire has used, and can stop a hire of your own.
- A lead is told a hire's short report with money, time, tokens and the files it changed, not its whole answer.
- Your "no" on a hire's work changes no file; the hire is told to fix it. The git tool can discard single files a hire changed.
- Only the pm and main may commit or release.
- Claims are by file: two hires cannot work on the same file.
- The pm enters its plan into the engine and is sent back while a step is open; main likewise. A pm idle for an hour starts a fresh session.
- A hire is called silent only when neither it nor any hire below it has shown a sign of life.
- A running hire's card says what it is doing now and which files each call looked at.
- `/autocontinue` starts the work, stays on through your questions, and ends only on `/autocontinue-off`, Esc or an escalation.
- A role's effort setting now reaches its agent. The `brains` tool can time a model and store a whole set of choices at once.

## Tools

- Tool explanations are about half as long, which costs every session fewer tokens.
- Fixed: adding a record component keeps constructor calls compiling; a staged coupled signature change behaves like a direct one; turning a function into a command keeps access to the old class's members; inlining keeps a lambda compiling.
- `generate` can add a default method, and add a method to a record or an enum.
- `search_symbols` without a kind finds methods and fields too; `find_string_literals` searches text blocks.
- `organize_imports` counts moved imports; `refresh_workspace` lists problems, errors first; the test runner sees the project's resource folders; `forbidden_edge` leaves tests out unless asked.
- New and moved code is indented as the project does, with spaces where it declares no formatter.
- A refusal for a missing login says how to connect.

## Known limits

- A memory lookup that never answers can still freeze the engine.
- Work built by several hires at once may fail to commit through the git tool.
- A hired agent can run on the model you picked for your own chat instead of its role's.
- After an engine restart the standing of the pm's plan is lost.
- The profiler agent cannot connect to a running program by itself.
- The new shell has not been tried with a real hired agent. Cursor agents cannot be held to it.
