# jawata-mcp v4.4.3

**A store its owner closed no longer keeps a database connection open behind it.**

## What went wrong

- **A closed experience store could stay open.** Closing the store drained only the connections sitting idle in its pool. A connection a background pass had borrowed at that moment was not seen, and when the pass handed it back the store put it into the emptied pool and left it open. An open file database keeps rewriting its lock file, so a folder deleted after the store was closed grew back. This is how `DestructiveVerbsBackUpFirstTest#the_rebuild_copies_first` failed once in 4.4.2's CI run: JUnit could not delete its temp folder because it was not empty.
- **A close landing between the closed-store check and the opening of a new connection** was not caught either; the new connection belonged to a store nobody could reach.

## What changes

- **A connection handed back after the close is closed**, not pooled.
- **A connection opened in the gap after the check is closed on the spot** and the caller is refused as if the check had seen the close.
- **New test `ACloseTakesEveryConnectionWithItTest`:** it failed on 4.4.2's code (the borrowed connection was still open after the close) and passes now.

## Known limits

- **The CI failure was not reproduced.** The class passed 25 of 25 runs on its own; the cause comes from reading the code and the CI log. The borrowed-connection leak is tested; the open-after-check gap is closed by the same change but has no test of its own.
- **The root cause of the shared store's "The database has been closed" on a resident's first write is not found** and is not claimed fixed here.

Works with jawata-studio 4.4.1. No studio release is needed.
